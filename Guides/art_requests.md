## R4. 돌담 조각 (`BG-ST*-WALL`)

벽이 납작한 띠 무늬라 "뱀처럼" 보인다. 컨셉 그림처럼 돌덩이가 하나하나 서 있는 담으로 바꾸는 그림.
게임 쪽은 준비 끝 — 지금은 벽 띠 그림을 네모로 잘라 임시 조각으로 세워 둠 (사방 같은 높이).

```text
# 요청: 방 둘레에 세우는 "돌담 조각" (스테이지 6곳 × 10개)

## 배경
탑다운(위에서 비스듬히 내려다봄) 픽셀아트 게임. 방의 벽을 좌우로 반복되는 띠 그림으로 그렸더니
돌의 입체감이 없고 무늬만 흐르는 띠처럼 보인다. 그래서 벽을 "서 있는 조각 그림"을 방 외곽선(곡선)을 따라
나란히 세워서 만들도록 바꿨다. 조각마다 윗선이 달라서 돌담이 울퉁불퉁해 보이는 것이 목표.
목표 그림: C:\workspace\claude\Game_Develop\OnionCat\Art\Concepts\Gameplay_v1\OnionCat_Gameplay_Concept_v1.png
  (방 둘레의 돌덩이 담 — 덩이마다 높이·모양이 다르고, 윗면과 앞면이 따로 보인다)

## 먼저 읽을 것 (재질·색 기준)
C:\workspace\claude\Game_Develop\OnionCat\Art\Final\Backgrounds\
  ST{n}\BG-ST{n}-SHAPE\Wall_Face.png · Wall_Cap.png   (지금 벽의 재질과 색 — 스테이지마다 이어받을 것. ST2는 유리 온실 벽 등 돌이 아닐 수 있음)
  ST{n}\BG-ST{n}-SCENERY\  Sprites\ + manifest.json     (서 있는 물건의 그림체·외곽선·manifest 형식을 똑같이)
  ST{n}\ST{n}_Assembly.png                              (스테이지 분위기)

## 만들 것 — 스테이지마다 10장, 새 폴더 ST{n}\BG-ST{n}-WALL\Sprites\
| 파일 | 캔버스(px) | 그림 폭 | 그림 높이 | 내용 |
|---|---|---|---|---|
| WALL_01 ~ WALL_05 | 128×160 | 96~112 | 104~136 | 보통 조각 — 돌 2~4덩이가 쌓인 담 한 토막. 5장의 윗선이 서로 다를 것 |
| WALL_06 ~ WALL_07 | 96×192 | 56~72 | 150~176 | 기둥 — 담보다 솟은 돌기둥 |
| WALL_08 ~ WALL_09 | 128×128 | 96~112 | 64~88 | 낮은 조각 — 허물어졌거나 낮은 담 |
| WALL_10 | 128×192 | 96~112 | 150~176 | 포인트 — 그 스테이지다운 것 하나 (등불 달린 기둥·덩굴에 덮인 담 등) |
+ manifest.json (BG-ST{n}-SCENERY의 것과 같은 형식: file · canvas · pivot_pixels · bounds), Proof.png

## 반드시 지킬 것 (게임이 이렇게 쓴다)
- 조각은 **돌리지 않고** 외곽선을 따라 조각 폭의 85% 간격으로 세운다 (이웃과 15% 겹침). 무작위로 좌우 반전한다.
  → 한쪽에서 빛이 오는 명암·글자·방향이 있는 것 금지. 좌우 어느 쪽으로 이웃이 와도 자연스러울 것.
- 방의 옆벽(세로로 달리는 벽)에서는 같은 조각이 **위아래로 약 40px씩 어긋나며 겹쳐 쌓인다** (아래 것이 앞).
  → 정면에서 본 그림 하나로 가로 줄·세로 줄 둘 다 담으로 읽혀야 한다.
- 조각마다 **윗면(위에서 내려다본 면, 높이 24~40px) + 앞면**이 구분되어 보일 것. 실루엣은 네모가 아니라 돌 모양대로 울퉁불퉁.
- 이웃과 겹쳤을 때 구멍이 안 나게: 보통 조각(01~05)과 낮은 조각(08~09)은 그림의 왼쪽 끝 12px·오른쪽 끝 12px 구간에서도
  불투명 부분의 높이가 그 조각 전체 높이의 55% 이상.
- 피벗 = 그림의 맨 아래 가운데 (발밑). 맨 아랫줄은 땅에 닿는 선 — 평평하게 (풀·자갈 몇 픽셀은 허용).
- 픽셀아트: 알파는 0 또는 255만. 96px = 게임 속 1유닛, 고양이 캐릭터 키 약 86px (보통 조각이 고양이보다 조금 큼).
- 캐릭터 그림과 같은 굵기의 어두운 외곽선.

## 합격 기준 (측정 가능)
- [ ] 6스테이지 × 10장 = 60장, 캔버스 크기가 표와 정확히 일치
- [ ] 알파 값은 0과 255뿐
- [ ] 그림 폭·높이(불투명 영역의 bounds)가 표의 범위 안
- [ ] 피벗: manifest의 pivot_pixels x가 그림 폭 가운데에서 ±8px 이내, y는 불투명 영역 맨 아랫줄
- [ ] 01~05·08~09: 양 끝 12px 구간의 불투명 높이 ≥ 전체 높이의 55%
- [ ] Proof.png (스테이지마다): Floor_Fill 위에 ① 조각 10개를 무작위 순서로 폭의 85% 간격으로 가로로 세운 줄
      ② 같은 조각 8개를 세로로 40px씩 어긋나게 쌓은 줄 (아래 것이 앞). 둘 다 틈 없이 담으로 보일 것

## 하지 말 것
- 기존 폴더(SHAPE·SHEET·SCENERY 등)의 파일 수정
- 문·출입구 그리기 (문은 따로 있음)
```

**오면 게임 세션이 할 일**: 가져오기(`Import Backgrounds` — 줄은 이미 있음) → 임시 조각이 새 그림으로 바뀜 · 담 높이·간격 조절.

## R5. 옆벽 출구 문 (`BG-ST*-DOOR` East·West)

방의 출구는 전부 오른쪽(동쪽) 벽에 있는데, 옆에서 본 문 그림이 얇은 문틀뿐이라 문인 줄 모른다.

# 요청: 옆벽(동·서)에 난 출구 문을 "문으로 보이게" 다시 그리기 (스테이지 6곳)

## 배경

플레이어가 "저기가 나가는 곳"이라고 한눈에 알아봐야 한다.

## 반드시 지킬 것
- 문을 옆에서 본 얇은 선으로 그리지 말 것. **문짝을 화면 쪽으로 약 45도 돌려 세운 것처럼**(평행사변형) 그려서
  문짝 면이 보이게 한다. 양옆에 돌기둥(또는 그 스테이지의 문기둥), 위에 가로대, 기둥에 등불 하나.
- East = 방의 오른쪽 벽에 서는 문 (방 안은 왼쪽). 문짝 면이 왼쪽 아래(방 안쪽)를 향한다. West는 그 반대.
- Closed = 문짝이 닫힘 (나무 문·쇠창살 등 "막혔다"가 분명히). Open = 문짝이 열려 안쪽으로 길이 보이고 등불이 켜짐.
  Closed와 Open은 기둥·가로대 위치가 픽셀 단위로 같을 것 (바뀌는 것은 문짝과 등불뿐).
- 피벗 = 문턱(문이 바닥에 닿는 선)의 가운데. manifest의 pivot_pixels에 적는다. 벽의 구멍은 세로 128px.
- 픽셀아트: 알파는 0 또는 255만. 96px = 1유닛.

- [ ] Proof.png: 돌담(또는 Wall_Face) 사이에 East 문을 세우고 고양이(Art\Final\Cats의 아무 그림)를 옆에 둔 그림 —
      문짝 면이 보이고 고양이보다 큼

## R6. 고정 장소의 건물 크기 (`BG-FARM · VILLAGE · GATE · TOWER`)

마을·농장의 집이 고양이만 해서 장난감처럼 보인다 (물건을 모두 128×192 캔버스에 맞춰 그린 탓).

```text
# 요청: 고정 장소 4곳의 건물·물건을 실제 크기감으로 다시 그리기

## 배경
탑다운(위에서 비스듬히 내려다봄) 픽셀아트 게임. 농장·마을·등대 입구·등대탑은 큰 바닥 그림 한 장(1536×768) 위에
물건 5개를 세운 장소다. 지금은 집·온실·우물이 고양이 캐릭터(키 86px)와 비슷한 크기라 장난감처럼 보인다.
고양이가 그 집에 들어갈 수 있어 보이는 크기로 키운다.

## 먼저 읽을 것
C:\workspace\claude\Game_Develop\OnionCat\Art\Final\Backgrounds\
  Fixed_Locations_Contact.png                 (지금 4곳 — 고양이와 건물 크기 비교)
  BG-{FARM|VILLAGE|GATE|TOWER}\
    BG-*-GROUND\BG-*-GROUND.png               (바닥 그림 1536×768)
    BG-*-OBJECTS\Sprites\OBJECTS_01~05.png + manifest.json   (바꿀 물건)
    BG-*_Assembly.png                         (바닥 + 물건을 얹은 합성 그림 1536×768)

## 만들 것 — 장소마다
- BG-*-OBJECTS\Sprites\OBJECTS_01~05.png : **번호와 물건 종류는 그대로**, 크기만 아래 표대로 다시 그림 (캔버스는 물건에 맞게 자유)
- BG-*-OBJECTS\manifest.json : canvas · pivot_pixels(발밑 가운데) · bounds 갱신
- BG-*_Assembly.png : 새 물건을 새 자리에 얹어 다시 만든 합성 그림 (1536×768)
- BG-*-GROUND : 물건 자리가 바뀌어 길·흙 자리가 안 맞으면 바닥 그림도 고칠 것 (크기 1536×768 유지)
- 예전 파일은 지우지 말고 *_v1 이름으로 남김

## 반드시 지킬 것 (게임이 이렇게 쓴다)
- 게임은 "합성 그림 − 바닥 그림"의 차이로 물건 자리를 찾고, 크기가 가장 닮은 물건과 짝짓는다.
  → 합성 그림에서 물건 5개는 **캔버스 안에 통째로** 들어가고, 서로 16px 이상 떨어져 있고(겹침 금지), 크기가 서로 달라야 한다.
  → 합성 그림은 바닥 그림 위에 물건 스프라이트를 그대로 얹은 것일 것 (그림자·수정 덧칠 금지 — 차이 계산이 어긋남).
- 큰 건물은 위쪽 가장자리나 구석에 둔다. 가운데 약 900×400px은 비워 둘 것 (고양이가 걷고 대화하는 자리).
- 고양이가 다가가 쓰는 물건(책·온실·화분·등불·샘물·가판대)은 발밑 앞쪽(아래)에 고양이가 설 빈 바닥이 100px 이상.
- 피벗 = 발밑 가운데. 알파는 0 또는 255만. 96px = 1유닛. 사선 탑다운 시점 (지금 그림과 같은 각도).

## 합격 기준 (측정 가능)
- [ ] 4곳 × 물건 5개 = 20장, 번호별 물건 종류가 예전과 같음
- [ ] 물건별 그림 높이·폭이 표의 범위 안
- [ ] 합성 그림 1536×768, 바닥 그림과 다른 픽셀이 정확히 5덩어리 (서로 16px 이상 떨어짐), 각 덩어리의 크기가 manifest의 bounds 크기와 ±2px
- [ ] 알파 값은 0과 255뿐
- [ ] Fixed_Locations_Contact.png를 새로 만들어 고양이(86px)를 옆에 세움 — 집이 고양이 키의 3.5배 이상

## 하지 말 것
- 물건 번호를 바꾸거나 물건 개수를 늘리기 (게임이 번호로 기능을 짝짓는다)
- 스테이지(ST1~6) 폴더 수정
```

**오면 게임 세션이 할 일**: 가져오기 → 물건 자리 확인 · 표식(이름표) 높이와 물건 빛 위치를 새 크기에 맞춤.
