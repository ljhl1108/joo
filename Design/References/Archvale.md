## 핵심 메커니즘

### 1. 링(Ring) 장비 시스템 — 핵심 차별점
- 전투 능력은 오직 **반지(Ring)**로만 결정됨
- 총 3~5개 슬롯에 공격용/방어용/유틸리티 링 조합
- 링 효과 예시: "적 처치 시 회복", "투사체 관통", "대시 시 주변 폭발"
- 아이템 수집이 곧 빌드 구성 → 심플하지만 조합 폭 넓음

### 2. 총알 지옥 + 근접 혼합
- 적이 다양한 탄막 패턴으로 사격
- 플레이어도 근접 무기(검, 도끼 등)와 원거리 무기를 조합
- 일부 적은 근접에만, 일부는 원거리에만 약점 존재 → **OnionCat과 직접 유사**

### 3. 2인 로컬 협력
- 2인 동시 플레이 지원 (같은 화면 분할 없이 함께)
- 각 플레이어 독립적인 링 빌드 가능
- 체력 공유가 아닌 각자 체력 관리

### 4. 오버월드 탐색
- Zelda 스타일 오버월드: 방과 방 사이를 자유롭게 이동
- 각 방 클리어 시 링/아이템 보상
- 숨겨진 방, NPC, 상점 포함

### 5. 세 종류의 바이옴
- 각 바이옴(숲, 유적, 동굴 등)마다 고유 적·장애물·보스
- 바이옴 진행 순서는 고정, 但 각 바이옴 내 방 배치는 일부 랜덤

### 6. 보스 패턴 — 탄막 기반
- 보스는 페이즈별로 탄막 패턴 변화
- 일부 보스는 약점이 특정 방향 또는 특정 무기 타입에만 있음

## 플레이어들이 사랑하는 것

1. **링 시스템의 심플함 + 깊이** — 초보도 쉽게 이해하지만 조합은 무궁무진
2. **코옵의 즐거움** — 2인이 함께 탄막을 피하며 협력하는 긴장감
3. **픽셀아트 퀄리티** — 2인 팀이 만들었다는 게 믿기지 않는 비주얼
4. **근접+원거리 혼합** — 적마다 다른 접근 요구로 단조로움 방지
5. **짧은 런 길이** — 한 세션에 완주 가능한 적절한 볼륨

## OnionCat 적용 포인트

### A. "특정 타입 약점" 시스템 — OnionCat 핵심 기둥 검증
- Archvale도 같은 개념: 일부 적이 근접/원거리 중 하나에만 약점
- OnionCat 구현 힌트: 적 클래스에 `DamageType weakTo` 필드 (Melee / Ranged / Both)
- 약점 타입에 맞는 공격 시 데미지 1.5~2배 + 시각 피드백(색상 변화, 사운드)

### B. 링 시스템 → OnionCat 펫 업그레이드 슬롯
- Cat과 Onion 각각 2~3개 "능력 슬롯" 보유
- 런 중 획득하는 능력은 마치 링처럼 장착/교체 가능
- 단순하게 시작해서 복잡하게 발전하는 곡선

### C. 2인 협력 체력 설계 비교
- Archvale: 각자 체력 독립 → 한 명이 죽어도 계속 가능
- OnionCat: 몸을 공유 → 하나의 체력 풀 → 더 강한 협동 의존성
- 두 디자인의 차이를 이해하고 OnionCat의 "공유 몸" 컨셉 강점 재확인

### D. 오버월드 방 탐색 → 방 선택 화면 UX
- Archvale의 Zelda식 이동보다는 OnionCat은 방 선택 카드 UI가 더 어울림
- 하지만 "다음 방 미리보기" 기능은 참고 가능: 방 타입(전투/상점/이벤트) 아이콘 표시

### E. 보스 페이즈 전환 → OnionCat 보스 약점 페이즈
- 보스 체력 50% 이하에서 패턴 변경 + 약점 타입 교체
- 1페이즈: 원거리만 통함, 2페이즈: 근접만 통함 → 협력 역할 전환 강요

### F. 픽셀아트 2인팀 레퍼런스
- 2인 팀도 높은 퀄리티의 픽셀아트 완성 가능하다는 증명
- 스프라이트 수를 줄이되 애니메이션 프레임수를 늘리는 전략 참고

## 기술 참고사항
- **탄막 구현**: 오브젝트 풀링 필수 (한 화면에 수십~수백 발 동시 존재)
- **2인 인풋**: 각 플레이어 독립 InputActionAsset 또는 PlayerInput 컴포넌트 2개
- **방 클리어 판정**: 방 내 모든 적 처치 → 문 열림 이벤트 → 링/아이템 스폰
