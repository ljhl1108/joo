## 핵심 게임 메카닉

### 공유 리소스 시스템
- 파티 전체가 **공유 차량 한 대**를 타고 이동 (마치 Cat + Onion이 한 몸인 것과 유사)
- 음식(Food), 연료(Fuel), 의료용품(Medical)을 파티 전체가 공유
- 자원 고갈 = 런 실패의 주요 원인 → 자원 관리가 협력의 핵심

### 캐릭터 시스템
- 플레이어는 고유한 특성(Traits)을 가진 생존자를 선택
- 한 캐릭터가 죽으면 **NPC 생존자**로 교체 가능 — 영구 사망(permadeath)
- 각 캐릭터는 근접/원거리 무기 선호도가 달라 자연스럽게 역할 분담 유발

### 랜덤 이벤트 (텍스트 기반)
- Oregon Trail 스타일의 텍스트 선택지 이벤트가 랜덤 발생
- "폐허에서 물자를 찾겠는가? 위험 감수 vs 안전 통과" 등의 결정
- 결과에 따라 캐릭터 사망, 자원 획득, 특수 NPC 합류 등이 발생
- **OnionCat 적용 포인트**: 방과 방 사이 "랜덤 이벤트 팝업" 삽입 아이디어 (이미 `Random_Event_Popup_System.md` 참고)

### 전투 시스템
- **탑뷰 2D 좀비 학살** — 근접(다양한 타격 도구)과 원거리(총기) 병행
- 무기 내구도 시스템: 무기가 닳으면 파괴됨 → 지속 수집 필요
- 공격 판정: 밀리 무기는 광역 스윙, 원거리 무기는 탄창 수 관리
- 좀비 물리 반응: 군중이 밀려오는 압박감 → **군집 행동 AI** (`Enemy_AI_FOV_Patrol_Flocking.md` 참고)

### 로그라이크 요소
- 런마다 지도 레이아웃, 이벤트, 자원 위치 등이 완전 랜덤
- 런 성공 후 새 캐릭터 타입과 특수 이벤트 잠금 해제 (메타 프로그레션)
- 난이도 곡선: 이동 거리가 늘수록 좀비 수/세기 증가

## 2인 코옵 설계 분석

### 공유 체력 vs 개별 체력
- 각 캐릭터는 **개별 HP**를 보유하지만 공유 자원(음식, 의료품)으로 치료
- 한 명이 죽어도 런이 즉시 끝나지 않음 (NPC로 교체) — **점진적 실패 구조**
- **OnionCat 적용**: Cat과 Onion이 공유 HP를 쓰는 현재 설계와 유사 개념. 하지만 DRTC처럼 "한 쪽이 쓰러져도 런 계속" 메카닉 추가 고려 가능 (Onion이 기절 시 Cat이 솔로 생존 30초 도전)

### 역할 분담의 자연스러운 유도
- 근접 무기 캐릭터는 앞줄, 원거리 무기 캐릭터는 뒷줄에 자연히 배치됨
- **OnionCat의 Cat(근접)/Onion(원거리) 구조와 완벽히 일치**
- DRTC: 명시적 역할 강제 없이 무기 타입으로 자연 유도 → OnionCat도 동일 철학

### 협력 압박 요소
- 한 명이 포위되면 다른 한 명이 구출 이동 필요
- 자원을 혼자 독점하면 파티 붕괴 → 소통 강제
- 좁은 통로에서 이동 방향 합의 필요

## 플레이어가 사랑하는 요소

1. **랜덤성의 깊이**: 텍스트 이벤트가 매 런마다 새로운 스토리를 만들어냄
2. **코옵의 자연스러운 긴장감**: 친구가 죽으면 실제로 슬프고 웃기고 당황스러움
3. **가볍고 즉각적인 반응**: 조작이 단순하지만 좀비 학살의 타격감이 살아있음
4. **캐릭터 다양성**: 수십 개의 생존자 타입 → 매 런 새로운 조합 실험 유도

## OnionCat 적용 포인트

| DRTC 요소 | OnionCat 적용 방향 |
|---|---|
| 공유 차량(공유 몸체) | Cat이 Onion을 "들고" 다니는 공유 몸체 개념 — 동일 철학 확인 |
| 무기 내구도 | Onion의 투사체 탄약 한정 (무한 X, 탄약 관리) 도입 고려 |
| 텍스트 랜덤 이벤트 | 방과 방 사이 선택형 이벤트 팝업 → 협력 결정 강화 |
| 점진적 실패 (NPC 교체) | Cat 또는 Onion 중 한 명이 기절해도 런 계속 — 30초 구출 타이머 |
| 근접/원거리 자연 역할 분담 | 기존 설계 방향성 검증됨. 적 약점 설계로 강화 |
| 좁은 공간 협력 압박 | 복도형 방 타입에서 Cat이 앞, Onion이 뒤 구도 강제 |
