# Indie QA Playtesting Process

리서치 날짜: 2026-11-10

## 개요

인디 게임에서 QA(품질 보증)와 플레이테스트는 별개의 단계다. **QA**는 버그·크래시·기술적 문제를 잡는 과정이고, **플레이테스트**는 재미·난이도·UX를 평가하는 과정이다. 대형 스튜디오와 달리 소규모 팀은 두 가지를 직접 체계화해야 한다.

OnionCat에서 필요한 이유:
- 2인 협동 게임은 싱글보다 테스트 경우의 수가 많음 (입력 조합, 동기화 오류)
- 장비 163종 + 세트 보너스 조합 오류는 플레이 중반에야 발견되는 경우가 많음
- 얼리 액세스·데모 출시 전 "치명적 버그 없음"을 보장해야 첫 인상을 망치지 않음

## Unity 구현 방법 (QA 도구 측면)

### 1. 테스트 매트릭스 — 입력 조합

OnionCat은 입력 조합이 복잡해서 매트릭스가 필수:

```
| 시나리오               | 패드 O | 패드 X | 패드 1P만 |
|------------------------|--------|--------|-----------|
| 메인 메뉴 조작         | [ ]    | [ ]    | [ ]       |
| 업그레이드 선택        | [ ]    | [ ]    | [ ]       |
| 패링 타이밍            | [ ]    | [ ]    | [ ]       |
| 합동기 동시 입력       | [ ]    | N/A    | N/A       |
| 가방 열기/닫기         | [ ]    | [ ]    | [ ]       |
```

각 항목을 버전마다 한 사람이 체크.

### 2. 세이브/로드 무결성 테스트

```
1. 1방 완료 후 강제 종료 (에디터 Stop)
2. 재실행 후 이어하기
   → 체크: 체력, 장비, 패시브, 작물 종류가 일치하는가?
3. 메타 진행도(온실 해금, 등불 색) 보존 확인
4. meta.json 직접 편집 후 로드 — 예외 처리 확인
```

### 3. 경계값 테스트 — 흔한 버그 위치

인디 게임에서 버그가 가장 많이 나오는 경계값:
- **방 클리어 직후 사망** — 보상 UI + 체력 0 동시 처리
- **업그레이드 선택 중 패드 연결/해제**
- **보스 사망 + 플레이어 사망 동시** — 엔딩과 게임오버 충돌
- **씬 전환 직전 발사체 존재** — 풀 오브젝트가 다음 방에 남는 현상
- **세트 보너스 5번째 장비 장착/해제** — 경계값 보너스 갱신 오류

### 4. 플레이테스트 세션 구조 (60분 세션 기준)

```
사전 (5분):
  - 테스터에게 게임 목표만 설명 ("최대한 멀리 가는 게임")
  - 조작 설명 없음 (튜토리얼 효과 측정용)
  - 화면 녹화 or 옆에서 관찰

플레이 (40분):
  - 개입 금지. 막혀도 기다림
  - 테스터가 소리 내어 생각하게 유도 ("지금 뭐가 이상한가요?")
  - 관찰 기록 항목: 첫 사망 위치/원인, 업그레이드 패턴, 혼란스러워하는 순간

사후 인터뷰 (15분):
  - "가장 재밌었던 순간은?"
  - "가장 불편했던 것은?"
  - "고양이/작물 중 더 재밌었던 것은?"
  - "다시 한다면 같은 작물을 고르겠나?"

```

### 5. 피드백 분류 — 행동/감정/의견 구분

테스터 피드백을 그대로 받아들이면 안 됨. 분류:
- **행동 관찰** (믿을 수 있음): "세 번째 방에서 대쉬 사용을 멈췄다"
- **감정 반응** (그대로 반영): "이 적이 불공평하게 느껴졌다"
- **의견·제안** (참고만): "대쉬를 더 빠르게 하면 좋겠다"

의견을 직접 구현하면 테스터의 취향 게임이 됨 — 행동 관찰로 원인을 파악해야 함.

### 6. 버그 보고 양식 (최소한의 형식)

```
## 버그 #NNN
- 증상: (무엇이 잘못됐나)
- 재현 순서: (1. 2. 3.)
- 재현율: 항상 / 가끔 / 한 번
- 심각도: 크래시 / 진행 불가 / 불편 / 외관
- 스크린샷/영상 첨부
```

에디터의 Player.log 경로: `%AppData%\..\LocalLow\Unity\<게임이름>\Player.log`

### 7. Unity Test Runner — 자동화 가능한 테스트

```csharp
// EditMode 테스트 — 세트 보너스 계산 검증
[Test]
public void SetBonus_TwoSunPieces_GivesExpectedBonus()
{
    var host = new PassiveHost();
    host.AddPiece(SunSet.Piece1);
    host.AddPiece(SunSet.Piece2);
    host.Recalculate();
    
    Assert.AreEqual(2, host.GetSetCount(SetType.Sun));
    Assert.IsTrue(CombatModifiers.Has(SetType.Sun, 1));
}
```

런 로직(세트 계산, 스탯 합산)은 자동 테스트로 커버, 나머지는 수동 테스트.

## OnionCat 적용 포인트

### 얼리 액세스 출시 전 체크리스트

```
크리티컬 (출시 불가 조건):
[ ] 모든 입력 조합에서 메인 메뉴 → 1방 → 클리어 가능
[ ] 중간 저장 → 이어하기 정상 동작
[ ] 보스 클리어 후 엔딩 화면 출력
[ ] 크래시 없이 30분 플레이 가능
[ ] 한글 텍스트 오탈자 없음 (UI 전수 검사)

중요 (출시 전 수정 권장):
[ ] 장비 10종 이상 조합 테스트 (스탯 오염 없음)
[ ] 세트 보너스 2→3→4→5착 전환 오류 없음
[ ] 패드 연결/해제 중 게임 멈춤 없음
[ ] 사망 → 처음부터 → 다시 1방 클리어 가능

일반 (출시 후 패치 허용):
[ ] 모든 방 모양에서 적 스폰 위치 오류 없음
[ ] 장비 아이콘 미싱 없음
[ ] 보스 패턴 2페이즈 이상 존재
```

### 2인 협동 고유 테스트

OnionCat처럼 2인 협동 게임에서만 발생하는 케이스:
- **한 명만 조작할 때** (싱글 플레이어가 양쪽): 고양이 혼자, 작물 혼자 각각 테스트
- **한 명이 움직이지 않을 때**: 협동하지 않는 경우에도 진행 가능한가
- **업그레이드 선택에서 의견 충돌**: UI 타임아웃(현재 없음?) 동작 확인
- **한 플레이어 패드 배터리 방전**: 중간 패드 해제 후 재연결 흐름

### 플레이테스트 초대 대상 우선순위

1. **완전 비게이머 1인** — 튜토리얼·UX 측정
2. **로그라이크 경험자 1인** — 난이도·장비 밸런스 측정
3. **개발자 지인 비게이머 커플/친구 2인** — 2인 협동 체험
4. 개발자 본인 플레이는 "버그 발견"에만 유효, "재미 측정"에는 거의 무효
