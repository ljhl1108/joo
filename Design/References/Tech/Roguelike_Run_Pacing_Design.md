# Roguelike Run Pacing Design

리서치 날짜: 2026-10-10

## 개요

"런 페이싱"이란 플레이어가 한 런(약 1시간) 동안 느끼는 **긴장·이완·성장·위기의 리듬**을 의도적으로 설계하는 것. 잘 설계된 페이싱은 플레이어가 "방금 이겼는데 왜 또 하고 싶지?"라는 느낌을 만든다. OnionCat은 1시간 런을 목표로 하므로 이 설계가 특히 중요하다.

## 핵심 이론: 긴장-이완 곡선

```
강도
 ▲
 │     [엘리트]              [보스]
 │   ╭──────╮           ╭──────────╮
 │  ╭╯  전투  ╰╮   [상점] ╭╯   보스 2P  ╰─ 클리어
 │ ╭╯           ╰─────────╯
 │╭╯ [시작방]                    
 │╯
 └──────────────────────────────── 시간
      보상 선택   휴식 정원
      ↑ 이완 포인트 ↑
```

- **긴장 포인트**: 전투방, 엘리트, 보스
- **이완 포인트**: 보상 선택 화면, 상점, 휴식 정원, 방 이동 페이드
- 긴장이 너무 오래 지속되면 → 피로감, 실수 증가
- 이완이 너무 많으면 → 지루함, 집중력 저하

### 이완 포인트의 역할
이완 포인트는 단순히 "쉬는 시간"이 아니라 **"다음 긴장을 준비하는 시간"**:
- 보상 선택 → 새 장비/카드를 얻고 다음 전략을 구상
- 상점 → 씨앗 소비로 선택의 무게감, "무엇을 살까?" 미니 퍼즐
- 휴식 정원 → 체력 회복 + 효과 갈아끼우기 = "이제 진짜 준비됐다" 느낌

## 룸 시퀀스 설계 원칙

### 원칙 1: 3+1 리듬
전투 3번 → 이완 1번이 기본 리듬. 연속 전투가 너무 많으면 전투 자체가 지루해짐.

```
OnionCat 런 순서 (현재):
시작 → 전투 → 전투 → [보물/엘리트] → 전투 → [상점/보물] → 전투 → 휴식 → 보스
```
전투 4번 사이에 이완 포인트 3번 = 건강한 리듬.

### 원칙 2: 파워 스파이크 타이밍
플레이어는 특정 순간에 "내가 강해진 느낌"을 받아야 한다. 이 스파이크 없이는 단조로워짐.
- **스파이크 1**: 첫 희귀 장비 획득 (대개 2~3번째 전투 후)
- **스파이크 2**: 세트 시너지 발동 순간 (세트 2세트 달성)
- **스파이크 3**: 보스 직전 휴식 정원 이후 — "풀 HP + 강화 빌드"

### 원칙 3: 위기 포인트 계획
**위기가 없으면 클리어의 성취감이 없다.** 엘리트나 보스에서 한 번은 "죽을 뻔했다" 순간이 있어야 함.
- 엘리트 = 체력 2배 + 크기 1.2배 → 난이도 스파이크
- 보스 2페이즈 = 패턴 속도 2배 → 극적 위기

## Unity 구현 방법

### 방 순서를 데이터로 관리 (DungeonManager.stagePlan)
```csharp
// 문자열 기반 런 계획 — 수정이 쉬움
string[] stagePlan = {
    "start",        // 시작방
    "combat",       // 전투
    "combat",       // 전투
    "elite|treasure", // 엘리트 또는 보물방 (50/50)
    "combat",       // 전투
    "shop|treasure",  // 상점 또는 보물방
    "combat",       // 전투
    "rest",         // 휴식 정원
    "boss"          // 보스
};
```

### 긴장도 측정 지표
```csharp
public class PacingMetrics : MonoBehaviour {
    public float CurrentTension => 
        (float)(consecutiveCombatRooms) / 3f;  // 0~1
    
    public bool NeedsRelief => 
        consecutiveCombatRooms >= 3 || playerHP < maxHP * 0.4f;
}
```

### 다음 방 유형 힌트 UI
출구 앞 표식 [A/B]가 "다음 방이 어떤 종류인지" 보여주면 플레이어가 현재 방에서의 전략을 조정할 수 있음:
```csharp
// 출구 표식에 다음 방 아이콘 표시 (보물=상자, 엘리트=해골, 상점=동전)
exitSignA.SetIcon(nextRoomTypeA.icon);
exitSignB.SetIcon(nextRoomTypeB.icon);
```

## OnionCat 적용 포인트

### 현재 상태 진단
현재 OnionCat 런 순서 (`DungeonManager.stagePlan`)는 이론적으로 건강하다:
- 전투 4개 + 이완 3개 + 보스 = 적절한 리듬
- **개선 여지**: 보스 전 마지막 전투방 → 휴식 정원 순서가 "클라이맥스 직전 긴장 고조"에서 "갑자기 이완"으로 느껴질 수 있음

### 개선 아이디어 1: 엘리트 전 긴장 고조
엘리트 방 바로 전에 전투방이 하나 더 있으면 "연속 2전투 → 파워 스파이크(엘리트 보상)" 리듬이 만들어짐. 현재보다 엘리트 보상의 감동이 커짐.

### 개선 아이디어 2: 보스방 입장 연출
보스방 페이드 전에 1~2초 "보스 이름 화면" 연출 추가 → 긴장 최고조. `Boss_Entrance_Presentation_System.md` 참고.

### 개선 아이디어 3: 런 중반 선택 분기
3스테이지 구조로 확장할 때 스테이지 2 종료 후 "다음 스테이지 어디로 갈지" 분기 선택을 추가하면 런마다 페이싱이 달라지는 효과. (`InRun_Branch_Map_System.md` 참고)

### 밸런스 테스트 체크리스트
- [ ] 플레이어가 보스 전까지 한 번이라도 "죽을 뻔했다" 경험이 있는가?
- [ ] 보상 선택이 전투 직후 자연스럽게 이어지는가 (너무 오래 걸리지 않나)?
- [ ] 휴식 정원에서 체력 회복 후 "이제 준비됐다"는 느낌이 드는가?
- [ ] 런이 45분 이상 60분 이하인가? (너무 짧으면 성장 느낌 부족, 너무 길면 피로)
