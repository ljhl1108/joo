# Closed Beta Management System

리서치 날짜: 2026-10-29

## 개요

인디 게임 1인 개발자가 출시 전 **비공개 베타 테스트**를 어떻게 운영하는지에 대한 가이드.
"베타 테스트"라고 하면 대규모 서버 스트레스 테스트를 떠올리기 쉽지만, 인디 로그라이크에서의
베타는 **10~50명의 집중 플레이어에게서 유의미한 피드백을 받는 단계**다.

OnionCat 기준: 출시 3~6개월 전 실시, 핵심 플레이 루프 완성 후 진행.

---

## 베타 테스트가 필요한 이유

혼자 만들면 혼자 테스트하게 된다 → **개발자 눈에는 익숙해진 결함이 보이지 않음**

베타로 발견하는 주요 문제:
- "이 규칙은 안내가 없으면 아무도 모른다"
- "이 난이도는 개발자한테는 쉽지만 처음 하는 사람한테는 불가능"
- "2인 협동이라는데 혼자 하면 AI 없어서 즐겁지 않음"
- "30분 해봤는데 장비 시스템이 뭔지 아직도 모르겠음"

---

## 베타 단계 설계

### 1단계: 알파 → 클로즈드 베타 기준
다음이 모두 갖춰진 후 베타 시작:
- [ ] 런 1개를 처음부터 끝까지 클리어할 수 있음
- [ ] 크래시 없이 30분 플레이 가능
- [ ] 기본 장비·보상 시스템 작동
- [ ] 기본 조작 설명 있음 (방법 몰라서 막히는 일 없게)

### 2단계: 베타 목표 설정
베타마다 **질문 1~3개만** 정한다. 전부 다 검증하려 하면 피드백이 흩어진다.

예시 질문:
- "협동 콤보 시스템을 처음 하는 사람도 발견하고 사용하는가?"
- "장비 선택 화면이 헷갈리지 않는가?"
- "3스테이지까지 클리어하는 데 적정한 시간이 드는가?"

## 베타 테스터 모집 방법

### 채널별 방법

| 채널 | 인원 | 특징 |
|------|------|------|
| 개인 지인 | 3~5명 | 솔직한 피드백, 게임 경험 다양 |
| Discord 서버 (자체) | 10~20명 | 게임에 관심 있는 사람들 |
| itch.io "Devlog + Beta Key" | 20~50명 | 모르는 사람의 시각, 더 객관적 |
| Reddit r/indiegaming / r/playmygame | 5~15명 | 영어권, 전문적 피드백 가능 |
| 한국 인디게임 커뮤니티 | 10~30명 | 한국어 UI 피드백 |

**OnionCat 2인 협동 특수 사항**: 2인 테스터를 쌍으로 모집해야 함
- "친구 데려와도 됩니다" 형식
- itch.io 베타 키를 2개 세트로 배포

### Steam 베타 배포 방법
1. Steam에 게임 등록 (출시 전이라도 가능)
2. `SteamWorks → 앱 → 브랜치` 에서 베타 브랜치 생성
3. 베타 패스워드 설정 → 테스터에게 패스워드 배포
4. 테스터: 라이브러리 → 속성 → 베타 → 패스워드 입력

### itch.io 베타 배포 방법
1. 프로젝트를 `Restricted (invite only)` 또는 `Password protected`로 설정
2. 베타 키를 CSV로 생성 → 배포
3. 가격을 `$0`로 유지하면 베타 키 없이도 무료 접근 가능

## 피드백 수집 시스템 설계

### 방법 1: 구글 폼 (가장 쉬움)
게임 종료 후 보여주는 링크 또는 QR코드.
질문 예시:
- 플레이 시간: ( ) 분
- 가장 재미있었던 점: (주관식)
- 가장 불편했던 점: (주관식)
- 2인 협동이 재미있었나요? (1~5점)
- 장비 시스템을 이해했나요? (네/아니오)
- 다음에 또 하고 싶나요? (네/아니오/모르겠음)

### 방법 2: 인게임 버그 리포트 버튼
- `F8` 키 → 현재 게임 상태 + 텍스트 입력 → `Application.persistentDataPath`에 JSON 저장
- 개발자가 다음 업데이트 시 로그 파일 수집
- 구현 팁:
```csharp
[Serializable]
public class BugReport {
    public string description;
    public string scene;
    public float runTime;
    public string[] activeItems;
    public string systemTime;
}
```

### 방법 3: Discord 전용 채널
- `#beta-feedback` 채널 생성
- 템플릿 핀 고정: "버전 / 발생 상황 / 재현 방법"
- 실시간 소통 가능 → 모호한 피드백을 바로 질문으로 명확화 가능

## 피드백 처리 워크플로우

### 수집 → 분류 → 우선순위 → 적용

```
수집 (3~7일) → 분류 스프레드시트에 정리 → 
카테고리: [버그/밸런스/UX/기능추가/칭찬] →
우선순위: [Critical/High/Medium/Low] →
다음 빌드 패치 노트에 반영
```

### 분류 스프레드시트 컬럼 예시
| 번호 | 테스터 | 카테고리 | 내용 요약 | 우선순위 | 처리여부 |
|------|--------|---------|---------|---------|---------|
| 1 | Tester_A | 버그 | 대쉬 중 문 통과 | Critical | ☑ |
| 2 | Tester_B | UX | 장비 카드 설명이 너무 작음 | High | ☑ |
| 3 | Tester_C | 밸런스 | 1스테이지 슬라임이 너무 빠름 | Medium | |

### 적용 기준
- Critical: 즉시 수정 → 핫픽스 배포
- High: 다음 베타 빌드에서 수정
- Medium: 정식 출시 전까지 수정
- Low: 시간 있으면 수정 (백로그)

## 베타 일정 설계 (OnionCat 예시)

```
[베타 1회차 - 4주]
  1주차: 테스터 모집 + 빌드 배포
  2주차: 자유 플레이
  3주차: 피드백 수집 마감
  4주차: 수정 + 다음 베타 준비

[베타 2회차 - 3주] (수정 사항 검증 집중)
  1주차: 새 빌드 배포
  2주차: 수정된 부분 집중 테스트 (특정 질문 제시)
  3주차: 최종 피드백 + Early Access/출시 결정
```

## 베타 테스터 예우

인디 게임에서 베타 테스터를 무시하면 나중에 홍보 자산을 잃게 된다:

- 최소: 크레딧에 이름 올리기 (`Special Thanks — Beta Testers`)
- 추가: 베타 전용 인게임 아이템 (코스메틱, 배경 등)
- Discord에서 별도 역할(Role) 부여: `🧪 Beta Tester`
- 정식 출시 때 무료 키 또는 할인 코드

## OnionCat 적용 포인트

### 2인 협동 특화 베타 설계
- 혼자 플레이 테스트와 **2인 플레이 테스트를 별도 진행** (경험이 다름)
- 혼자 테스트: 솔로 플레이 가능성, AI 파트너 필요 여부 확인
- 2인 테스트: 협동 콤보 발견률, 합동기 사용 횟수, 장비 분배 갈등 여부

### 베타 전 체크리스트
- [ ] 게임 크래시 없이 30분 가능
- [ ] 기본 조작 방법 알 수 있는 화면 있음
- [ ] 버그 리포트 방법 설명 (Discord 링크 또는 F8 버튼)
- [ ] 베타 전용 디버그 메뉴 (`OnionCat > Debug`) 비활성화 확인
- [ ] meta.json 리셋된 상태로 배포 (개발자의 진행 상황이 테스터에게 노출되지 않게)

### 특히 물어봐야 할 것
1. "장비 세트 보너스를 플레이 중에 인식했나요?"
2. "합동기 게이지를 어떻게 채우는지 알았나요?"
3. "2인이 각자 다른 캐릭터를 조작하는 게 자연스러웠나요?"
4. "런 1개의 길이가 적당했나요? (너무 길다/딱 좋다/더 길어도 됨)"
