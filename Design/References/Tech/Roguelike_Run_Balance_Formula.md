# 로그라이크 런 밸런스 공식 설계

리서치 날짜: 2026-10-27

## 개요

로그라이크에서 수치 설계는 "재미있는 느낌"을 반복 가능하게 만드는 핵심 기술이다. 데미지가 너무 작으면 싸움이 지루하고, 너무 크면 한 방에 죽는다. HP가 너무 많으면 끝이 없고, 너무 적으면 불안하다. 이 문서는 OnionCat처럼 1시간 런 구조의 게임에서 **데미지 공식, HP 곡선, 보상 경제** 를 수학적으로 설계하는 방법을 다룬다.

---

## 1. 기본 설계 원칙 3가지

### 원칙 1: 처치 시간(Time-to-Kill) 기준 설계

숫자를 설계할 때 시작점은 "이 적은 몇 대에 죽어야 하나?"이다.

| 적 유형 | 적정 처치 타수 | 이유 |
|---------|--------------|------|
| 잡몹 (슬라임) | 5~7타 | 너무 빠르면 존재감 없음, 너무 느리면 피로 |
| 중간 적 | 10~15타 | 전략적 우선순위 결정이 필요한 시간 |
| 엘리트 | 25~40타 | 장비 차이가 드라마틱하게 느껴지는 범위 |
| 보스 | 60~100타 (페이즈당) | 패턴을 충분히 경험하는 시간 |

**타수 계산 예시** (OnionCat 현재 수치):
- 기본 할퀴기 데미지: `15`
- 슬라임 HP: `30` (소규모) → 기본 공격 2타. 너무 적다 → `×5` 배율 적용 후 HP `150` → 10타 → 범위 상단
- 현재 CLAUDE.md에 명시: "처치 시간 임시 기준선: 새 적은 표 hp ×5"

### 원칙 2: 배율을 통한 성장 설계 (Multiplicative Scaling)

덧셈 성장: `데미지 = 기본 + 장비 보너스` → 초반에 강하고 후반에 약해짐 (선형)  
곱셈 성장: `데미지 = 기본 × (1 + 보너스A) × (1 + 보너스B)` → 복합 장비일수록 폭발적

로그라이크의 카타르시스는 곱셈 성장에서 온다.

```
예시:
기본 데미지 15
할퀴기 강화 +40% → ×1.4 = 21
속성 약점 ×2 = 42
세트 보너스 +30% → ×1.3 = 54.6
협동 콤보 ×1.5 = 81.9

후반 잘 조합된 공격: 기본의 5.4배
```

이 배율 차이가 "성장했다"는 느낌을 만든다. 그러나 지나치면 후반에 적도 엄청나게 세져야 해서 설계가 복잡해짐.

**권장 최대 배율**: 런 끝의 최대 DPS가 런 시작의 **4~6배** 이내로 유지.

### 원칙 3: 실효 체력 (Effective HP) 개념

플레이어가 "실제로" 버티는 체력은 명목 HP × 방어율이 아니다.

```
실효 HP = 명목 HP × (1 + 방어율) + 실드 × 평균 타수
          + 패링 절약 + 대쉬 무적 절약
```

OnionCat의 경우:
- 공유 HP 100
- 실드 기본 1칸 → 큰 공격 1회 무효화 (예: 적 강공격 30 데미지 절약)
- 실효 HP ≈ 100 + 30 (실드) + 30 (패링 1회 기대치) = ~160

설계할 때 "플레이어는 사실 HP 160짜리"로 생각하면 적 데미지 수치를 과소 설계하지 않음.

## 2. HP 곡선 설계

### 스테이지별 HP 배수 공식

적의 HP를 스테이지에 따라 선형이 아닌 **완만한 지수 곡선**으로 올리는 것이 일반적.

```
stage_hp_multiplier = base_hp × (1 + difficulty_per_stage × stage_index)

권장 값:
- difficulty_per_stage = 0.25~0.35
- 스테이지 0 (시작): ×1.0
- 스테이지 1: ×1.3
- 스테이지 2: ×1.6
- 스테이지 3 (보스): ×2.0 (또는 보스 전용 고정값)
```

플레이어 성장이 이 배수를 따라잡거나 약간 앞서야 "강해진 느낌"이 있다.

### OnionCat 적용 예시

현재 슬라임 기본 HP 30 → ×5 = 150.

스테이지별 실제 목표:
| 스테이지 | 슬라임 HP | 고양이 기본 처치 타수 | 후반 빌드 처치 타수 |
|---------|---------|-------------------|----------------|
| 0 (정원) | 150 | 10타 | 2~3타 |
| 1 (중간) | 195 | 13타 | 3~4타 |
| 2 (탑) | 240 | 16타 | 3~5타 |
| 보스 | 480~600 | 32~40타 | 8~12타 |

강화된 빌드로 보스도 12타 안에 죽이면 너무 쉬움 → 보스 HP를 2배로 계획하거나 보스 전용 피해 감소.

## 3. 데미지 수식 설계

### 기본 공식 (OnionCat에 맞춘)

```csharp
float CalcDamage(float baseDmg, float atkStat, float defStat, 
                 float multA, float multB, float typeBonus)
{
    // additive: 스탯 보정
    float effective = baseDmg * (1f + (atkStat - 10f) * 0.05f);
    
    // 방어 감소 (비선형 — 너무 높은 방어가 무적이 되지 않도록)
    float defFactor = 100f / (100f + defStat);
    
    // multiplicative: 각 보너스 독립 곱셈
    float bonuses = multA * multB * typeBonus;
    
    return effective * defFactor * bonuses;
}

// 예시:
// baseDmg = 15, atkStat = 10 (기본), defStat = 0
// multA = 1.4 (세트 보너스), multB = 2.0 (약점)
// typeBonus = 1.0 (속성 없음)
// 결과: 15 × 1.0 × 1.0 × 1.4 × 2.0 = 42
```

**방어 감소 공식의 의미**: `100 / (100 + def)` 형태는 디아블로/PoE에서도 쓰임.
- def 0: 100% 피해
- def 100: 50% 피해  
- def 300: 25% 피해

방어가 올라갈수록 효과가 줄어들어 "방어만 올리면 무적" 방지.

### 크리티컬 설계

크리티컬이 있다면:

```csharp
float critRoll = Random.value;
float finalDmg = critRoll < critRate ? damage * critMulti : damage;

// 권장 기본값:
// critRate = 0.05 (5%)  → 기대 DPS 증가: ×1.05 (미미)
// critMulti = 2.0       → critRate = 0.2일 때 기대 증가 ×1.2
```

크리티컬이 너무 강하면 운 편차가 커짐 → 짧은 전투에서 "불공평하다" 느낌. 로그라이크에서는 크리티컬보다 **세트 보너스 같은 확정 배율**이 게임 흐름을 더 좋게 만든다.

## 4. 보상 경제 설계

### 씨앗(재화) 획득 곡선

OnionCat 현재 구조:
- 처치 1씨앗 + 전투방 클리어 5씨앗 (엘리트 15) + 분해
- 상점 가격: 일반 15 · 희귀 30 · 에픽 60 · 전설 120

**목표**: 런 1회에 상점에서 2~3개 구입 가능하되, 전설은 정말 특별해야 함.

계산 예시 (16전투방 + 엘리트 4회 런):
```
처치: 방당 평균 8마리 × 16방 × 1씨앗 = 128
방 클리어: 16 × 5씨앗 = 80
엘리트: 4 × 15씨앗 = 60
분해 (평균 2개 분해, 방당): 런당 약 30씨앗
합계: ~298씨앗

상점 방문 2번 × 리롤 가능: ~250씨앗 지출
에픽 2개 구입(120씨앗) + 리롤 2회(20씨앗) = 140씨앗 → 가능
전설 1개(120씨앗) + 에픽 1개(60씨앗) = 180씨앗 + 리롤 → 빠듯
```

이 범위면 상점이 의미 있으면서도 "전설 모아서 사기" 플레이는 어렵다 → 적당.

### 장비 드롭률 설계

기대 획득 배율 계산:
```
런 1회 드래프트 기회: 16전투방 × 2명 = 32카드 선택
바닥 아이템: 방당 0.5개 × 16 = 8개

세트 보너스 2단계 달성에 필요한 세트 아이템 수: 2개
32선택 × 세트 아이템 비율 40% × 원하는 세트 비율 20% ≈ 2.56개 기대

→ 2단계는 런 1회에 높은 확률로 달성 가능 ✓
4단계는 집중해야 가능 ✓  
6단계는 전략적 선택이 필요 ✓
8단계는 극히 드문 특별한 런 ✓
```

## 5. 밸런스 튜닝 프로세스

### 1단계: 기준선 설정 (Baseline Run)

- 장비 없이 (기본 장비만) 보스까지 가는 "기준 런" 플레이
- 처치 시간, 생존 시간, 씨앗 적립 기록
- 이 기준선이 모든 조정의 기준

### 2단계: 상한/하한 테스트

- **최악의 경우 (잘못된 드래프트)**: 랜덤 선택만으로도 3스테이지 진입 가능해야 함
- **최선의 경우 (완벽한 세트)**: 보스가 무력하게 보이지 않아야 함

### 3단계: 분산 확인

동일 빌드 3~5회 반복으로 결과 분산 측정. 표준편차가 평균의 30% 이내이면 "예측 가능한 어려움".

### 4단계: 플레이어 감각과 수치 일치

```
"강하다고 느끼는 빌드"는 실제로 강해야 함:
- 할퀴기 강화 세트 → DPS 수치 의미있게 증가
- 실드 강화 세트 → 생존 시간 의미있게 증가
- 씨앗 경제 장비 → 상점 접근성 의미있게 증가
```

수치와 감각이 불일치하면 숫자를 감각에 맞게 조정 (항상 수치가 우선이 아님).

## Unity 구현 — OnionCat에 바로 쓸 수 있는 패턴

```csharp
// PlayerStats.cs에서 최종 데미지 계산
public float GetClawDamage()
{
    float base_dmg = Current.ClawDamage;                      // 장비에서 집계된 기본값
    float atk_bonus = 1f + Current.GetStat(StatType.Attack);  // 덧셈 보너스 합산 먼저
    
    // 각 곱셈 배율 독립 적용
    float set_mult = CombatModifiers.GetDamageMultiplier();
    float crit_mult = Random.value < Current.CritRate ? Current.CritMulti : 1f;
    
    return base_dmg * atk_bonus * set_mult * crit_mult;
}

// 적 DifficultyScaling.cs
public float ScaleHp(float baseHp, int stageIndex)
{
    return baseHp * (1f + 0.3f * stageIndex);
}
```

## OnionCat 적용 포인트

1. **현재 ×5 배율(hp 기준선)**: 슬라임 150, 방패 근위병 300 — 기본 공격 10~20타. 적당한 범위.
2. **세트 보너스 2단계**: 확인 필요 — 플레이어가 2단계를 "항상" 느낄 수 있는가? 2단계 효과가 15% 이하면 체감 못함 → 30~40% 이상 권장.
3. **실드 실효 HP 활용**: 방어적 장비를 받았을 때 "버티는 느낌"이 나는지 테스트.
4. **씨앗 경제 재검토**: 위 계산 기준으로 상점에서 에픽 2개 정도 구입이 "알뜰한 런"이 되도록 튜닝.
