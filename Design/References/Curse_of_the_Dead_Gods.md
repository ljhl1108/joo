## 핵심 메커니즘

### 1. 저주(Curse) 시스템 — 핵심 차별점
- 전투 중 어둠 속에 있거나 함정에 닿으면 **부패(Corruption)** 게이지가 쌓임
- 게이지가 가득 차면 랜덤 **저주(Curse)** 부여: 근접만 가능, 체력이 조금씩 빠짐 등 단점
- 저주는 누적 가능(최대 3개), 4번째 때 **신의 형벌(Divine Punishment)**으로 보스 소환
- 동시에 저주는 특정 조건을 달성하면 **해제** 가능 → 리스크-리워드 구조

### 2. 세 가지 무기 슬롯
- 주무기(메인), 보조무기(서브), 특수무기 각 1개 장착
- 각 무기는 **스탯 보정 타입**(힘/민첩/신앙)과 연결
- 세 무기 모두 같은 타입 → **"완벽한 조화" 보너스** (시너지 시스템)

### 3. 어둠/빛 관리
- 횃불로 방 밝히면 안전, 어둠에 있으면 부패 누적
- 일부 적은 어둠 속에서만 공격 → 빛을 조절해 싸우는 전략 요소

### 4. 골드 = 체력
- 골드를 소비할 때 체력도 함께 소모 (HP처럼 작동)
- 아이템 구매와 생존 간 트레이드오프 극대화

### 5. 챔피언(Champion) 적
- 일반 적이 랜덤 능력을 가진 챔피언으로 등장
- "화염 면역", "넉백 시 반격" 등 다양한 모디파이어 조합

### 6. 저주 사원 구조
- 세 개의 서로 다른 사원(Path) 존재
- 각 사원은 고유 테마, 적, 트랩, 보스를 가짐
- 런마다 하나의 경로를 선택

## 플레이어들이 사랑하는 것

1. **부패/저주 시스템의 긴장감** — 불가피한 저주를 어떻게 활용할지 고민하는 메타 게임
2. **무기 시너지 탐구** — 세 무기 조합으로 빌드 다양성 극대화
3. **챔피언 변형 시스템** — 같은 적이라도 모디파이어에 따라 전혀 다른 전투
4. **어둠 관리의 전략성** — 빛과 어둠을 오가는 포지셔닝 게임
5. **간결한 조작** — 복잡하지 않은 대신 리스크 관리가 깊음

## OnionCat 적용 포인트

### A. "저주 = 패널티지만 활용 가능" 구조 → 양날의 버프 시스템
- OnionCat에서 **체력이 낮을 때 발동하는 조건부 강화** 도입 가능
- 예: Cat이 30% HP 이하일 때 슬래시 범위 2배, Onion의 투사체 속도 증가
- 플레이어가 위험 상태를 일부러 유지하려는 고차원 플레이 유도

### B. 골드=체력 트레이드오프 → 자원 통합 설계
- 런 내 업그레이드 선택 시 **체력 소모** 선택지 추가 가능
- "강력한 패시브를 얻는 대신 최대 HP -10" 같은 의미 있는 결정

### C. 챔피언 모디파이어 시스템 → 적 다양성 증폭
- OnionCat 적에 1~2개 랜덤 태그 붙이기: "방패형(근접 무적)", "빠른형(이동속도 2배)", "회복형"
- 코드 구현: 적 클래스에 `ModifierList` 필드 + 스폰 시 `ApplyModifiers()` 호출

### D. 경로(Path) 선택 → 런 시작 시 테마 선택
- 런 시작 전 3개 경로 카드 제시, 각 경로는 적 타입·보상 유형 예고
- 협력 게임이므로 두 플레이어가 합의해야 선택 → 협력 의사소통 강화

### E. 어둠/빛 관리 → 시야 제한 메커닉
- 일부 방에 "어두운 방" 모디파이어 적용: 시야 반경 제한
- Cat(근접)은 유리, Onion(원거리)은 불리 → 역할 균형 자연스럽게 흔들기

## 기술 참고사항
- **비전투 위협**: 트랩(가시, 불꽃, 구덩이)이 부패를 유발하면서 맵 탐색 자체가 긴장감 있음
- **적 AI**: 챔피언은 기본 AI에 플래그를 추가하는 형태로 구현 — Unity에서도 동일하게 `EnemyBase` + `ChampionModifier` 컴포넌트로 가능
- **비주얼**: 어둠 표현에 URP의 2D Light를 활용, 횃불은 Point Light로 구현
