## 핵심 메카닉

### 1. 비동기 고스트 시스템 (Async Ghost System)
Phantom Abyss의 가장 독창적인 시스템. 같은 사원을 이전에 도전한 플레이어들의 **반투명 유령**이 동시에 화면에 표시된다.

- 유령은 해당 플레이어가 **실제로 했던 경로를 그대로 재현**
- 유령이 죽은 자리에 **유령이 고정**되어 그 위치에 위험이 있음을 암시
- 플레이어는 유령들의 실패를 보고 덫 위치/타이밍을 **간접 학습**
- 죽은 유령의 채찍을 획득 가능 → 유령이 남긴 유산 계승

### 2. 사원 단 한 번의 클리어 (Single-Claim Temple)
- 특정 사원은 **최초로 클리어한 사람만** 보상 획득
- 클리어 후 해당 사원은 "은퇴" → 더 이상 새 도전 불가
- 자신이 클리어한 사원은 **혼자 다시 도전** 가능 (연습 모드)
- **데일리 사원**: 매일 리셋되어 전 세계 플레이어와 경쟁

### 3. 채찍 시스템 (Whip System)
- 채찍으로 **벽/천장에 그래플링** → 공중 이동
- 다양한 채찍 타입: 기본형 / 긴 거리형 / 더블 스윙형 / 속도형
- 채찍마다 **고유 패시브 능력** 보유
- 죽은 유령의 채찍 습득 시 그 유령의 채찍 능력 상속

### 4. 가디언 저주 (Temple Guardian)
- 일부 사원 방에 **추적형 가디언** 스폰
- 시간이 지날수록 가디언 이동 속도 증가
- 탐색 속도와 위험 회피 사이의 **긴장감** 조성

### 5. 절차적 사원 생성
- 방마다 다른 **덫 조합** (회전 칼날, 낙석, 불꽃, 구덩이 등)
- 런마다 고유 레이아웃 → 재플레이성 확보

## 플레이어들이 사랑하는 것
1. **"혼자인데 혼자가 아닌" 감각**: 유령들이 동시에 달리는 장면이 마치 함께하는 것처럼 느껴짐
2. **유령의 실패가 정보가 됨**: 유령 무덤이 많은 방 = "이 방이 위험하다"는 직관적 신호
3. **최초 클리어의 영구성**: 내가 그 사원을 "정복했다"는 기록이 남음
4. **유령 채찍 상속**: 다른 플레이어와 간접적으로 연결되는 감각

## OnionCat 적용 포인트

### 1. 비동기 협동의 철학: "상대방이 할 수 없는 것"의 분담
Phantom Abyss는 완전한 솔로 게임이지만 고스트 시스템으로 **협동감을 만들어낸다**. 이 철학을 OnionCat에 응용:
- P1(고양이): 이동/생존/근접 담당 → "몸"
- P2(파/양파): 조준/원거리/방패 담당 → "눈과 손"
- 두 역할이 명확히 분리될수록 "파트너가 나를 보완한다"는 협동감이 강해짐

### 2. 죽음이 정보가 되는 디자인
유령의 사망 위치가 덫 정보를 전달하듯, OnionCat에서도 죽음 정보를 활용:
- 이전 런에서 가장 많이 죽은 방 번호를 HUD에 표시 → 자기 학습 피드백
- 죽음 위치에 반투명 고스트 고양이 배치 (미래 구현 아이디어)
- `RunHistory.GetDeathCountInRoom(roomId)` 데이터를 난이도 조절 신호로 활용

### 3. 점진적 위험 공개 (Progressive Danger Reveal)
Phantom Abyss에서 플레이어가 조심스럽게 방 내부를 탐색하며 덫 패턴을 학습하듯:
- OnionCat 방 설계: 첫 등장 시 **덫 텔레그래프**를 충분히 보여줌
- 반복 등장 시 텔레그래프 시간 단축 → 숙련자 도전 과제
- 플레이어가 "이전에 이 패턴에서 죽었다"를 기억하도록 일관성 있는 패턴 유지

### 4. 고스트 시스템 소규모 적용 아이디어
본격 구현이 어려우면 간단한 버전으로:
- 런 시작 시 "지난 런에서 N번 죽었습니다" 메시지 표시
- 가장 많이 죽은 방에 경고 아이콘 표시 (자체 플레이 데이터)
- 구현 힌트: `PlayerPrefs`에 `deaths_room_{id}` 정수 저장
