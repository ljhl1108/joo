## 핵심 메커니즘

### 장르 혼합 구조
Hammerwatch II는 순수 로그라이크가 아닌 **RPG + 로그라이크 하이브리드**다.
- **오버월드**: 타운, NPC, 퀘스트가 있는 고정 오픈월드
- **던전**: 절차적으로 생성되는 랜덤 층
- 이 두 층위 구조가 초보 개발자에게 "완성도" 기준을 제시한다

### 클래스 시스템
- 7개 클래스: Paladin, Ranger, Wizard, Warlock, Thief, Priest, Sorcerer
- 각 클래스는 주무기 공격, 보조 스킬, 궁극기 3단 구성
- **협동 시너지**: Priest의 힐 + Paladin의 탱킹처럼 역할이 자연 분리됨

### 레벨 & 아이템 진행
- **퍼마데스 없음**: 클래스 레벨이 런 간 유지 (메타 진행)
- 장비(장비 슬롯 5개) + 인챈트 + 스킬 트리 조합
- 런마다 랜덤 보물 상자, 상점, 이벤트로 다양성 확보

### 4인 협동 특성
- 화면 공유: 전원 한 화면에 묶이지 않고 **개별 자유 이동** (화면 밖 나가면 리스폰 지점으로 복귀)
- 죽으면 팀원이 부활시켜 주거나 체크포인트에서 부활
- **난이도 스케일링**: 플레이어 수에 따라 적 체력/수 자동 증가

### 피드백 & 주요 루프
- 히트 시 골드 드롭 → 상점 구매 → 더 강한 적 처치
- 던전 클리어 보상 → 마을 건물 업그레이드 → 영구 버프

## 플레이어들이 좋아하는 것

1. **클래스 다양성**: 7개 클래스가 명확히 다른 플레이 스타일 제공
2. **협동 자유도**: 각자 다른 역할로 자연스럽게 협력하게 유도
3. **픽셀아트 연출**: 풍부한 애니메이션, 파티클, 라이팅으로 픽셀아트를 "고급화"
4. **낮은 진입 장벽**: 퍼마데스 없어서 실패해도 성장이 남음

### 비판받는 점
- 스토리가 약하고 오버월드 콘텐츠가 얇음
- 랜덤 던전이 후반엔 반복적으로 느껴짐
- 최적화 문제 (출시 초기)

## OnionCat 적용 포인트

### 1. 협동 역할 분리의 설계 철학
Hammerwatch II는 클래스로 역할을 나누고, OnionCat은 몸을 공유하며 Cat(근접)/Crop(원거리)으로 역할을 나눈다. **핵심 원칙은 같다**: 각 플레이어가 "내가 없으면 팀이 무너진다"는 필요성 느끼기.

OnionCat 적용:
- 근접만 통하는 적, 원거리만 통하는 적 외에 **둘 다 써야 죽는 보스**도 설계
- Cat이 방어하는 동안 Crop이 충전 공격하는 시너지 패턴 추가

### 2. 화면 공유 없는 2인 협동 처리
Hammerwatch II처럼 두 플레이어가 화면 경계에 구애받지 않는 협동 설계. OnionCat은 한 몸이라 자동으로 이 문제가 해결되지만, **카메라가 두 입력에 모두 반응**해야 한다는 힌트.

→ 카메라를 Cat 위치 기준으로 두고, Crop의 마우스 조준 방향으로 미세 오프셋 적용하는 방식 검토

### 3. 퍼마데스 vs 메타 진행 균형
Hammerwatch II는 퍼마데스를 포기하고 레벨 유지. OnionCat은 로그라이크이므로 퍼마데스가 기본. 하지만 **런 간 영구 잠금 해제**(신규 아이템 풀, 적 로그, 배경 스킨)를 메타 보상으로 추가하면 초보자 이탈율 낮출 수 있음.

### 4. 클래스별 느낌 차별화 → OnionCat 고유 업그레이드 경로
Hammerwatch II의 7클래스처럼 OnionCat 업그레이드도 Cat 특화 / Crop 특화 / 시너지 3가지 경로로 나누기:
- Cat 특화: 대시 횟수 증가, 슬래시 범위 확대, 방어 강화
- Crop 특화: 투사체 수 증가, 관통력, 재장전 속도
- 시너지: Cat이 대시할 때 Crop 투사체 강화, 패리 성공 시 Cat 속도 상승
