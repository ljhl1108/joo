## 핵심 메카닉

### 1. 역할 분리형 협력 (Role-Differentiated Co-op)
- ToeJam: 느리지만 힙하고 여유로운 무드, 플레이어가 리드 캐릭터
- Earl: 빠르지만 덜렁대는 성격, 서포트/탐색 역할
- **두 캐릭터가 물리적으로 분리 가능**: 화면이 스플릿되거나, 같은 공간을 공유하거나
- 각 캐릭터가 다른 아이템 효율을 가짐 (ToeJam은 음악 아이템 효율 높음)

### 2. 공유 세계 + 개별 플레이어 공간
- 같은 레벨을 탐색하지만 각자 독립적으로 이동
- 카메라: 두 플레이어가 멀어지면 자동으로 분할 화면 → 가까워지면 합쳐짐 (다이나믹 스플릿 스크린)
- **OnionCat과의 차이점**: OnionCat은 항상 같은 몸에 붙어 있음

### 3. 아이템 시스템 & 불확실성
- 아이템을 집어도 처음엔 라벨이 없음 → 직접 써야 효과 확인 (Binding of Isaac 스타일)
- 같은 아이템이 런마다 다른 이름을 가질 수 있음
- 긍정/부정 아이템이 섞여 있어 탐욕이 리스크를 낳음

### 4. 로그라이크 구조
- 맵: 절차적으로 생성된 섬들 (하늘 위 떠다니는 섬 형태)
- 각 섬에 다양한 캐릭터(NPC), 적, 아이템 분포
- 수직 이동(낙하 = 아래 섬으로): 높이가 난이도를 대체
- 퍼머데스 X — 되살아날 수 있지만 파트너의 도움이 필요

### 5. 생존 & 복귀 메카닉
- 쓰러진 플레이어를 파트너가 부활시킬 수 있음
- 둘 다 쓰러지면 게임 오버 (진정한 협력의 필요성 강제)

## 플레이어들이 좋아하는 것

1. **즉석 협력의 카오스**: 파트너가 나쁜 아이템을 써서 둘 다 당하는 웃긴 상황
2. **다이나믹 스플릿 스크린**: 화면 분할이 자연스럽게 일어나는 방식
3. **아이템 라벨 발견의 재미**: "이게 뭔지 모르지만 써보자" → 기대감/두려움 공존
4. **원작 향수**: 오리지널 1991년 작의 느낌 재현
5. **다양한 NPC 인터랙션**: 재미있는 캐릭터들과의 유쾌한 대화

## OnionCat 적용 포인트

### 역할 분리의 명확성
ToeJam&Earl처럼 두 플레이어가 뚜렷하게 다른 강점을 가져야 한다:
- Cat(P1): 근접 위협 제거, 돌진 회피, 물리적 포지셔닝 담당
- Onion(P2): 원거리 위협 처리, 방향 지정 쉴드, 정보 싸움 (더 멀리 볼 수 있는 조준)

### 역할 강제 적 설계
ToeJam&Earl이 두 캐릭터의 속도 차이를 이용하듯, OnionCat도:
- **근접만 약점인 적**: Cat이 반드시 전면에 나서야 함
- **원거리만 약점인 적**: Onion이 정확히 조준해야 함
- **두 역할 동시 요구**: 쉴드로 막으면서 Cat이 돌진하는 조합 플레이

### 아이템 불확실성 도입 검토
업그레이드를 처음엔 이름만 보이고 효과를 알 수 없게 하는 방식 → 선택의 긴장감 증가

### 파트너 부활 시스템
쓰러진 플레이어를 파트너가 살려줄 수 있는 시스템 → Coop_Revival_System.md 참고
