## 핵심 메카닉

### 1. 역할 분리 Co-op (Divided Role Co-op)
- **1인 플레이**: 이동 + 무기 모두 혼자 조작
- **2인 Co-op**: Player 1 = 이동 / 사격, Player 2 = 보조 시스템 조작 (보조 포탑, 실드, 특수 무장)
- 두 플레이어가 **항상 다른 역할**을 수행해야 하는 구조 → 협력이 선택이 아닌 필수

### 2. 방어 시스템 돌파 (Breach Mechanics)
- 각 적 요새에는 **여러 방어 시스템**이 존재 (실드 제너레이터, 자동포탑, 경보 시스템, AI 코어)
- 플레이어는 어떤 시스템을 먼저 무력화할지 **전략적으로 결정**
- 실드가 살아있으면 코어에 피해 불가 → 특정 공격 방법 필요
- 일부 방어 시스템은 **근거리 공격**으로만, 일부는 **원거리**로만 파괴 가능

### 3. 사전 장비 선택 (Pre-Run Loadout)
- 런 시작 전 **예산 제한** 안에서 무기·보조 장치 선택
- 강력한 장비일수록 비용 ↑ → **트레이드오프 선택**
- 런 중 새 장비 획득 가능하지만 초기 빌드 계획이 핵심

### 4. 적 알람 & 증원 (Alarm & Reinforcement)
- 플레이어가 알람을 트리거하면 **증원 적** 소환 → 난이도 급상승
- 알람 시스템을 먼저 파괴하면 증원 없이 조용히 진행 가능
- "시끄럽게 가거나 조용히 가거나" 전술 선택지

### 5. 리스크-보상 구조
- 더 어려운 요새 = 더 좋은 보상
- 피해 입으면 수리 비용 발생 → 과욕은 금물
- 런 경제 시스템: 돈 → 수리비 + 다음 런 장비

## 플레이어들이 좋아하는 것

1. **역할 특화 Co-op** — 두 플레이어가 진짜 다른 역할을 하는 느낌
2. **전략적 침투 계획** — 방 입장 전 시스템 배치 분석 후 순서 결정
3. **빌드 다양성** — 무기 조합이 많아 매 런 다른 느낌
4. **픽셀아트 우주 분위기** — 버려진 외계 요새의 공포스러운 분위기
5. **예측 가능한 위협** — 적 배치가 파악 가능해 학습 재미 있음

## OnionCat 적용 포인트

### 1. 역할 강제 분리 설계 교훈
- Cryptark의 두 플레이어는 **동일한 행동을 하지 않음**
- Cat(이동+근접) ↔ Onion(조준+원거리+방어) 분리 설계와 완벽히 일치
- 설계 원칙: "한 플레이어만으로는 모든 상황 대처 불가능하게"

### 2. 적 취약점 시스템 레퍼런스
- Cryptark: 방어막 → 원거리만 가능, 코어 → 근접만 가능
- → OnionCat: **근접형 적** = 원거리 공격에 취약, **원거리형 적** = 근접 공격에 취약
- 이 시스템이 "왜 두 플레이어가 협력해야 하는가"를 자연스럽게 설명

### 3. 예산 기반 업그레이드 선택
- Cryptark: 런 시작 전 예산 제한으로 장비 선택
- → OnionCat: 업그레이드 선택 시 **포인트 풀** 방식 도입 가능
  - "강력한 조합 = 비쌈" → 자동 밸런스
  - 런마다 빌드 방향성 결정의 재미

### 4. 알람/증원 메카닉 활용
- → OnionCat: 특정 엘리트 적이 살아있으면 주기적으로 잡몹 소환
- 또는: 소음이 큰 전투(폭발 등) → 인근 방 적이 경계 모드 진입
- "조용한 처리" vs "정면 돌파" 전술 선택지 추가

### 5. 리스크-보상 방 선택
- → OnionCat 던전: 더 어려운 방(적 수 ↑, 위험 환경)에 더 좋은 업그레이드 배치
- 플레이어가 스스로 난이도를 선택하는 느낌
