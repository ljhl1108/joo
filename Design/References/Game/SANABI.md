## 핵심 메카닉

### 1. 체인 무기 — 이동 + 전투의 통합
SANABI의 모든 것은 **체인** 하나에서 출발한다. 플레이어는 체인을 벽·천장에 걸어 스윙으로 이동하거나, 적에게 걸어 끌어당기며 공격한다. 단일 도구가 이동계와 전투계를 동시에 담당하는 설계다.

- **Grapple & Swing**: 걸어서 진자 운동으로 속도 획득 → 적시에 해제 → 공중 가속
- **Enemy Pull**: 적을 향해 체인 발사 → 적을 당기거나 플레이어가 적에게 달라붙어 근접타
- **Momentum Physics**: 속도가 누적되므로 "느리게 걷기"가 본질적으로 불가능. 항상 스윙·낙하·도약 중

### 2. 보스전 — 텔레그래프 → 처벌 창 구조
SANABI의 보스는 모두 **명확한 선행 동작(텔레그래프)** 을 보여준 뒤 공격한다.
- 공격 직전 자세 변화(0.4~0.8초)
- 플레이어가 회피 완료 후 보스의 반격 불가 시간(딜 창) 2~3초
- 화면을 가득 채우는 탄막 패턴 — 피할 수 있는 "레인"이 반드시 1개 이상 존재

### 3. 원히트 킬 + 즉시 리스폰
체크포인트 기반 원히트 킬. 사망 패널티 거의 없음(2~3초 안에 같은 자리 리스폰). 이 구조 덕분에 플레이어가 겁 없이 공격적으로 플레이하고, 빠른 시행착오로 패턴을 익힌다.

### 4. 스토리 통합 — 플레이 흐름 안의 내러티브
컷씬이 별도 화면이 아닌 **인게임 공간** 안에서 전개된다(플레이어는 여전히 조작 중). NPC와의 대화, 환경 연출이 플레이어를 멈추지 않고 흘러간다.

### 5. 픽셀아트 + 임팩트 프레임
- 히트 순간 1~2프레임 히트스톱
- 적 피격 시 흰색 플래시(hit flash)
- 보스 등장 시 배경 색상 전환 (atmospheric shift)
- 폰트·UI도 모두 픽셀 아트 스타일로 통일

## 협동 요소

SANABI는 싱글플레이어 게임이지만, **이동과 전투의 역할 분리** 개념이 OnionCat과 직결된다.

| SANABI 요소 | OnionCat 적용 방향 |
|-------------|------------------|
| 체인 = 이동 + 전투 동시 | Cat(이동+근접)과 Crop(조준+원거리)이 한 몸에서 서로 다른 역할 |
| 원히트 킬 → 리스폰 없는 두려움 | 두 플레이어가 공유 체력 → 한 명의 실수가 팀 전체에 영향 |
| 텔레그래프 → 처벌 창 | OnionCat 보스에서 동일 패턴 적용 시 효과적 |
| 인게임 나레이션 | 방 클리어 후 Cat 독백 텍스트로 스토리 전달 |

## 플레이어가 사랑하는 것

1. **체인 이동의 숙달감**: 처음엔 어색하지만 익숙해지면 손가락이 춤추는 느낌
2. **감정적인 스토리**: 딸을 찾는 노병 이야기 — 픽셀아트임에도 눈물 리뷰 다수
3. **보스의 연출미**: 등장 컷씬, 페이즈 전환, 배경음악 변화 모두 극적
4. **짧고 알찬 볼륨**: 8~10시간 완주, 리플레이 동기 충분

## OnionCat 적용 포인트

### A. "하나의 도구 — 두 역할" 설계 철학
SANABI의 체인이 이동+전투를 통합하듯, OnionCat의 "공유 몸체" 컨셉도 **Cat과 Crop이 서로의 빈틈을 메우는 구조**여야 한다. Cat이 근접으로 들어갈 때 Crop은 자동으로 사격 각도를 확보하는 식으로 두 역할이 물리적으로 연동되어야 한다.

### B. 보스 텔레그래프 설계 참고
SANABI 보스 패턴의 핵심: **"경고 → 공격 → 처벌 창"** 의 3단계 리듬. OnionCat에서도 보스 공격 직전 0.5초 자세 변환 애니메이션 + 처벌 창 2초 확보. Cat과 Crop이 각자 역할로 처벌 창을 최대 활용하게 설계.

### C. 히트 피드백 레퍼런스
SANABI의 피격 표현(히트스톱 1~2프레임 + 화이트 플래시 + 적 넉백)을 OnionCat 근접·원거리 히트 피드백의 직접 레퍼런스로 활용. 특히 **약점 공격 성공 시** 이 피드백을 더 강하게 연출하면 "올바른 조합" 플레이의 보상감이 높아진다.

### D. 리스폰 설계 — 허들 낮추기
OnionCat도 초반에는 "사망 → 즉시 방 시작점 리스폰" 방식으로 진입 허들을 낮출 수 있다. 로그라이크 특성상 런이 끝나는 것은 사망 아닌 "방탈출 실패"가 아니라 "스택 누적 한계"로 설계하면 SANABI의 시행착오 문화를 흡수 가능.
