# It Takes Two

리서치 날짜: 2026-07-17

## 기본 정보

- **개발사**: Hazelight Studios (Josef Fares 감독)
- **장르**: 3D 플랫포머 협력 어드벤처
- **출시**: 2021년 3월 26일
- **공식 사이트**: https://www.ittakestwo.com/
- **Steam**: https://store.steampowered.com/app/1426210/It_Takes_Two/

## 핵심 설계 철학

### "협력이 스토리다"
- 두 캐릭터(Cody·May)가 이혼 위기의 부부 → 협력을 통해 관계 회복
- **메카닉이 내러티브를 강화**: 각 챕터의 협력 메카닉이 그 챕터의 감정 주제와 일치
  - 예: "집착" 챕터 → 하나가 끌어당기면 다른 하나가 저항하는 메카닉
  - 예: "신뢰" 챕터 → 서로 보이지 않는 곳에서 신호 보내며 진행

### "게임 디자인 쇼케이스"
- 한 게임 안에 40+ 개의 독립적 메카닉
- 각 챕터마다 완전히 다른 게임플레이 (슈터, 플랫포머, 퍼즐, 레이싱, RTS 등)
- 메카닉을 반복하지 않고 소개·심화·종료하는 극단적 커브

---

## 핵심 메카닉 패턴 분석

### 비대칭 능력 시스템

| 챕터 | P1 (Cody) 능력 | P2 (May) 능력 | 협력 핵심 |
|------|----------------|----------------|-----------|
| 나무 시작 | 망치 (못 박기) | 못뽑기 | 번갈아 가며 고정/해제 |
| 눈사태 | 시간 느리게 | 순간 이동 | 슬로우 + 이동 콤보 |
| 서커스 | 복제 | 원거리 조작 | 복제로 스위치 유지 |
| 파리 정원 | 생명력 부여 | 수분(식물 자라게) | 조합 퍼즐 해결 |

### 매 챕터마다 새 메카닉 - 설계 원칙
```
챕터 구조:
1. 튜토리얼 공간 (5분) — 새 능력 소개
2. 활용 공간 (10분) — 기본 퍼즐
3. 심화 공간 (15분) — 두 능력 복합 사용
4. 보스/클라이맥스 — 능력을 극한 활용
5. 감정적 마무리 — 메카닉 퇴장
```

## 협력 설계의 황금 원칙 (OnionCat에 직접 적용)

### 원칙 1: "나 없이는 불가능" (Dependency)
- 모든 퍼즐이 두 플레이어 모두 없으면 진행 불가
- 한 플레이어가 기다리는 시간 최소화
- **OnionCat 적용**: 근접+원거리 의존 적 설계, 방패 파리 시 Cat이 근접 대시 지원

### 원칙 2: "각자 빛날 순간" (Spotlight Rotation)
- P1이 주역인 구간과 P2가 주역인 구간을 번갈아 설계
- 한 플레이어가 계속 "도우미" 역할에 머물지 않도록
- **OnionCat 적용**: 근접 적 → Cat 주역, 원거리 적 → Onion 주역, 보스 → 번갈아 주역

### 원칙 3: "함께 발견" (Shared Discovery)
- 두 플레이어가 동시에 "오!" 하는 순간 설계
- 개인 발견이 아닌 공동 발견 경험
- **OnionCat 적용**: 두 명이 동시에 조건 충족 시 비밀 방 해금, 협력 피니셔 발동

### 원칙 4: "의도적 소통 유발" (Communication Forcing)
- 화면을 나눠 보여 서로 정보가 다를 때 소통 필수
- 타이밍 싱크가 필요해 "3, 2, 1..." 카운트다운 자연 발생
- **OnionCat 적용**: Cat만 보이는 함정 알림 HUD, Onion만 감지하는 원거리 적 레이더

### 원칙 5: "실패해도 재밌다" (Fun Failure)
- 협력 실패 시 코믹한 장면 연출 → 실패도 경험의 일부
- **OnionCat 적용**: 두 플레이어 사망 연출이 개별적 재밌는 애니메이션

## 보스 전투 설계 (가장 중요한 참고 포인트)

### It Takes Two 보스전 구조
```
페이즈 1: 단순 비대칭
  → P1 탱킹/어그로, P2 원거리 공격

페이즈 2: 역할 교환
  → 보스 패턴 변화로 P1/P2 역할이 뒤바뀜
  → "아까는 니가 공격했으니 이번엔 내가!"

페이즈 3: 완전 합동
  → 두 능력이 동시에 필요한 최종 패턴
  → 성공 시 극적인 피니셔

클라이맥스: 협동 피니셔
  → P1+P2가 동시 입력 → 보스 최종 처치
  → 감정적 클라이맥스 연출
```

### OnionCat 보스 설계에 직접 적용
```
페이즈 1: 방어막 보스
  [Cat] → 근접 슬래시로 방어막에 균열 생성
  [Onion] → 균열 부위에 투사체 집중 발사

페이즈 2: 역할 반전
  보스가 "원거리 면역 필드" 활성화
  [Cat] → 필드 생성기를 근접으로 파괴해야 함 (리스크)
  [Onion] → Cat을 따라다니며 잡몹 처리 지원

페이즈 3: 동시 입력 피니셔
  [Cat] 특수 슬래시 + [Onion] 차지 발사 동시 → 협력 피니셔
  판정 범위 넉넉하게 (동시성 ±0.3초 이내)
```

## 스코프 관리 교훈 (초보 개발자에게)

| 문제 | It Takes Two 해법 | OnionCat 적용 |
|------|------------------|--------------|
| "다양성 부족" | 챕터마다 다른 메카닉 | 층마다 1개 특수 방 타입 추가 |
| "협력 강요 느낌" | 메카닉으로 자연스럽게 | 약점 시스템으로 강요 없이 유도 |
| "한 명이 심심함" | 항상 둘 다 할 일 | 보조 역할도 게임플레이 있게 |
| "단순 반복" | 메카닉 퇴역 시스템 | 업그레이드로 기존 능력 심화 |

## 플레이어가 사랑하는 것

1. **끝없는 신선함**: 1시간마다 게임 장르가 바뀌는 느낌
2. **감정적 연결**: 스토리와 메카닉이 같은 감정을 전달
3. **평등한 재미**: 양 플레이어 모두 "내가 기여했다" 느낌
4. **소통의 즐거움**: 협력하며 쌓이는 추억
5. **완성도**: 버그 없는 깔끔한 완성 게임

---

## OnionCat 핵심 적용 포인트 요약

1. **역할 교환 보스 페이즈** — "이번 페이즈는 Onion 주역" 명확한 신호
2. **협력 피니셔** — 동시 입력 필살기 (판정 넉넉하게)
3. **정보 비대칭 활용** — Cat에게 미니맵, Onion에게 원거리 레이더
4. **메카닉 소개→심화→퇴역** — 매 층마다 새 협력 기믹 1개
5. **보스 구조 공식** — 비대칭 → 역할 교환 → 합동 피니셔
