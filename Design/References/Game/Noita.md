# Noita

리서치 날짜: 2026-08-28

- **장르**: 물리 시뮬레이션 로그라이크 액션

- **플랫폼**: PC (Steam)
- **공식 사이트**: https://www.noita.fi/
- **Steam**: https://store.steampowered.com/app/881100/Noita/

## 핵심 메커니즘

### 1. 픽셀 물리 시뮬레이션 (Falling Sand Engine)
- 게임 내 모든 픽셀이 물리적으로 시뮬레이션됨
- 물, 불, 기름, 산(acid), 용암 등이 실제처럼 흘러다님
- 총알 한 발이 물리적으로 액체를 튀김
- 환경이 완전 파괴 가능 (destructible environment)
- **핵심 필러**: "모든 것이 시뮬레이션된다 (Every pixel matters)"

### 2. 완드(Wand) 시스템 — 로그라이크 핵심
- 플레이어는 완드를 장착하고, 완드에 "스펠(Spell)" 카드를 조합
- 스펠 조합 방식:
  - `Explode + Bounce + Triple Scatter` → 폭발하는 튕기는 3발 탄
  - 같은 스펠이라도 순서에 따라 완전히 다른 결과
- 완드 자체에 속성: 발사 속도, 마나 재충전, 홀드 가능 스펠 수
- 조합 발견이 플레이어 성장의 핵심 재미

### 3. 죽음의 영구성과 세계 영구성
- **퍼마데스** + 하지만 **세계 씨드는 고정**
- 같은 월드에서 다시 시작 → 이전 런에서 무언가를 놓고 와도 그 자리에 있음
- 이전 런의 시체가 남음 (다른 플레이어의 유령도 볼 수 있음)
- 죽은 이유를 분석하고 다음 런에 전략을 바꾸는 구조

### 4. 평행 세계(Parallel Worlds) 시스템
- 세계 경계 밖으로 나가면 평행 세계로 진입
- 평행 세계는 기본 세계와 동일하지만 난이도가 올라감
- 숨겨진 비밀, 보스, 엔딩이 평행 세계에 존재

### 5. 비선형 탐험 구조
- 정해진 룸 순서 없음 — 원하면 최종 보스 근처로 바로 파고 내려갈 수 있음
- 레이어별 바이옴: 숲 → 광산 → 정글 → 빙하 → 지옥
- 탐험 vs. 최적화 경로 선택이 플레이어에게 있음

---

## 협동 요소

- **Noita는 싱글플레이 전용** — 공식 코옵 없음
- 그러나 **모드로 코옵 구현** (Noita Together 모드 등)
  - 두 플레이어가 같은 픽셀 세계를 공유
  - 물리 시뮬레이션이 공유 → 한 플레이어가 산(acid)을 쏘면 상대방도 위험
  - **우발적 배신(Friendly Fire)이 메인 콘텐츠**가 됨

---

## 플레이어들이 사랑하는 것

1. **발견의 쾌감**: 스펠 조합 → 완전히 예상 못한 효과 발견
2. **물리 상호작용**: 불을 붙여서 기름 호수에 튀기면 폭발 → 의도치 않은 연쇄 반응
3. **깊은 비밀**: 공식 위키도 완전히 정리 못한 숨겨진 시스템 (퀀텀 엔티티, 신성 선물 등)
4. **죽음의 재미**: "어떻게 죽었는지"가 재미있는 게임 — 자신의 폭발에 죽기, 중력이 뒤집혀서 죽기
5. **커뮤니티 탐험**: 4년이 지나도 새로운 비밀이 발견됨

## OnionCat 적용 포인트

### A. 환경 상호작용으로 취약점 체계 확장
- Noita: 물 + 전기 = 감전 피해
- **OnionCat 응용**: 특정 적이 "물 웅덩이" 위에 있으면 레인지 공격 연쇄, 특정 지형에서 냥이(고양이)의 대시가 추가 효과
- 취약점을 "단순 무기 타입"을 넘어 **환경 조건**으로 확장 가능

### B. 스펠 조합 → 업그레이드 조합 시스템
- Noita의 스펠 조합처럼 **런 업그레이드를 조합하면 예상 밖의 시너지** 발생
- 예: "공격력 +30%" + "모든 공격 관통" → 범위가 넓어질수록 강해짐
- 초보 개발자에게: 조합 로직 없이 단순 곱연산으로도 의도치 않은 시너지 발생 → 그것도 재미

### C. 예상 못한 죽음 → 학습 루프
- Noita의 "왜 죽었지?"가 다음 런 동기 부여
- **OnionCat**: 게임 오버 화면에 "마지막 피해 발생 원인" 표시 (근접 적/원거리 적/함정)
- 두 플레이어가 죽음 원인을 분석해서 다음 런 역할 분담 조정

### D. 씨드 고정 + 퍼마데스 구조
- Noita처럼 동일 씨드에서 재시작 → **"이번엔 다른 경로로"** 학습 가능
- OnionCat: 첫 런은 씨드 고정 → 2번째부터 완전 랜덤 옵션 고려

### E. 소규모 팀 물리 → 성능 교훈
- 3인 팀이 픽셀 물리 엔진 직접 제작 → C/C++ 코어, GPU 활용
- **OnionCat 교훈**: Unity 물리는 픽셀 단위 시뮬레이션에 부적합 → 파티클 이펙트로 "시뮬레이션처럼 보이게" 연출하는 것이 현실적

## 핵심 시스템

### 1. 픽셀 물리 시뮬레이션 ("모든 픽셀이 시뮬레이션된다")

Noita의 정체성. 모든 픽셀이 재질(물, 용암, 모래, 나무, 가스 등)로 정의되며 실시간 물리 법칙을 따른다.

- **액체**: 실제처럼 흘러내림 (물, 용암, 산성)
- **기체**: 위로 퍼짐 (연기, 증기)
- **화학 반응**: 물 + 용암 = 돌 + 증기, 불 + 나무 = 연소 + 연기
- **완전 파괴**: 모든 지형 파괴 가능 → 창의적 문제 해결 가능
- **기술적 구조**: 64×64 픽셀 청크 분할, dirty rect 최적화, marching square 강체 물리

**핵심 가치**: 의도하지 않은 연쇄 반응이 게임플레이의 재미 자체가 됨 → 창발적 게임플레이

### 2. 완드 빌딩 시스템

Noita의 두 번째 기둥. 주문(Spell)과 변환자(Modifier)를 조합해 완드를 커스터마이징.

| 요소 | 설명 |
|------|------|
| 완드 최대 보유 수 | 4개 |
| 비셔플 완드 | 순서대로 주문 발사 |
| 셔플 완드 | 주문 순서 랜덤화 |
| 주문 변환자 | 바로 오른쪽 주문에 속성 추가 (유도, 분열, 폭발 등) |
| 트리거 주문 | 탄환이 충돌 시 추가 주문 발동 |
| 체인소 주문 | 캐스트 딜레이 0으로 만들어 강력한 연계 가능 |

### 3. 퍼크 시스템 (런별 성장)

- 각 Holy Mountain(안식처) 통과 시 3개 중 1개 선택
- 리롤 비용: 200 → 400 → 800... (배로 증가)
- 일부 퍼크는 중첩 가능 → 파워 스케일링
- 총 103종+ 퍼크 존재

### 4. 11종 피해 유형 + 적별 저항/약점

| 피해 유형 | 특징 |
|----------|------|
| Melee / Slice | 근거리 |
| Projectile | 원거리 탄환 |
| Fire / Ice / Electric | 원소 |
| Explosive / Toxic / Physics / Curse | 특수 |

- **로봇 적**: 폭발·전기에 약함, 일반 탄환에 강함
- **Lukki(거미)**: 냉동 후 근접 타격에만 취약 → 두 가지 피해 유형 조합 필수
- 이 구조가 OnionCat의 "근접만 약한 적/원거리만 약한 적" 콘셉트와 직결

### 5. 바이옴 구조 (진행 구조)

**메인 경로**: 석탄 구덩이 → 눈 지하 → Hiisi 기지 → 지하 정글 → ...
**Holy Mountain**: 바이옴 사이 안식처 (완드 편집, 상점, 퍼크 선택)
**절차적 생성**: 바이옴마다 최대 22종 랜덤 변형 적용

### 6. 메타 진행 없음 (의도적 설계)

- 런 간 영구 해금/강화 없음
- 성장 = 플레이어 지식 + 실력
- 높은 진입 장벽이지만, 커뮤니티는 이를 장점으로 인식

## 플레이어가 사랑하는 이유

1. **창발적 물리**: 다른 게임에서 불가능한 고유한 경험
2. **완드 창의성**: "내가 필요한 도구를 직접 만드는" 느낌
3. **탐험 보상**: 정보 자체가 자산 (위키 없이는 모르는 것들)
4. **극강의 리플레이성**: 진행 구조 단순하나 매 런이 전혀 다름

**공통 불만**: 너무 어렵다, 설명이 없다, 급사한다 → 하지만 이게 Noita의 정체성

## OnionCat 적용 포인트

### 1. 적 약점 분기 시스템 ★★★
Noita의 11종 피해 유형 → 적마다 약한 피해 유형 고정 → 협력 강제
- OnionCat: Cat(근접) 전담 적 / Crop(원거리) 전담 적을 명확히 구분
- 시각적 피드백으로 구분 즉시 인식 가능하게 (색상, 실루엣, 움직임 패턴)

### 2. 퍼크 시스템 → 런 내 업그레이드 구조
- "안식처(rest zone)"에서 3개 중 1개 선택하는 구조 그대로 차용 가능
- Cat용 퍼크 / Crop용 퍼크 / 공유 퍼크로 분류
- 리롤 비용 배가 구조 → 골드 의사결정 긴장감

### 3. 환경 상호작용 퍼즐
- Noita 물리만큼 복잡하진 않아도, 환경 요소(물, 폭발물 등)를 두 플레이어 역할로 분담
- 예: Crop이 폭발물을 원거리로 폭파 → Cat이 열린 길로 돌진

### 4. 창발적 협력 시너지
- Cat의 무적 대시 + Crop의 유도탄 = "Cat이 떼어 모은 적무리를 Crop이 일제 사격"
- 미리 계획된 게 아닌 플레이 중 발견하는 조합의 재미

### 5. 멀티플레이어 미지원이 기회
- Noita는 솔로 전용 (공식 코옵 없음) → 커뮤니티 수요 증명
- OnionCat의 코옵 핵심 기계는 Noita가 채우지 못한 공백

### 6. 피해야 할 것
- 무설명 철학: 코옵 게임은 두 플레이어 간 명확한 피드백 필수
- 너무 복잡한 빌딩 시스템: 초보자 개발자로서 범위 관리 중요
