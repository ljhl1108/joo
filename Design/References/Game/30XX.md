## 핵심 시스템 분석

### 두 캐릭터 — OnionCat과 가장 유사한 구조

| | Ace | Nina |
|---|---|---|
| 역할 | 근접 메인 | 원거리 메인 |
| 기본 공격 | 에너지 블레이드 (단검) | 에너지 볼트 (탄환) |
| 특수 능력 | 대시 어택, 콤보 슬래시 | 마우스/조이스틱 조준 사격 |
| 레벨 디자인 최적 구간 | 밀집된 적, 근접 공간 | 탁 트인 복도, 거리 유지 |
| 협동 시너지 | Ace가 적 어그로 → Nina가 자유 조준 | Nina가 원거리 약화 → Ace가 마무리 |

**핵심 인사이트**: OnionCat과 역할 구조가 거의 동일. 30XX에서 검증된 설계를 직접 참고 가능.

### 협동 메커닉 — 공유 자원 & 부활 시스템

- **공유 화폐**: 두 플레이어가 같은 골드 풀 사용 → 상점에서 누가 살지 협의 필요
- **부활**: 파트너가 쓰러지면 시간 제한 내 파트너 위치로 이동 → 부활 터치 → 실패 시 체크포인트 복귀
- **동시 부활 불가**: 둘 다 동시에 죽으면 런 실패 → 한 명이 살아있어야 유지
- **실드 공유**: 특정 파워업(Augment)이 파트너에게도 효과 적용되는 "공유형" 존재

### 절차적 레벨 생성

- **월드 구조**: 6개 월드, 각 월드 = 여러 "스테이지" + 보스방
- **방 조합**: 핸드크래프트 방 + 절차적 조합 (방-to-방 연결)
- **분기 루트**: 각 월드에서 2~3개 경로 중 선택 (단순 vs 위험 but 보상)
- **시드 공유**: 동일 시드로 같은 레벨 재생성 가능 (클리어 재현, 친구와 공유)

### 파워업(Augment) 시스템

- **런 내 수집**: 방 클리어 → 3개 Augment 중 선택
- **캐릭터별 Augment**: Ace 전용, Nina 전용, 공용(공유)으로 분류
- **공유 Augment**: 둘 다 효과 받음 → 협의해서 선택 필요
- **시너지**: 특정 Augment 조합 시 숨겨진 효과 발동 (시너지 기반 빌드)

### 보스 패턴 — 협동 요구 설계

30XX 보스의 특징:
- **Ace 전용 취약 타이밍**: 보스가 방어막 전개 시 원거리 무효, 근접만 통함
- **Nina 전용 취약 타이밍**: 빠른 돌진 후 경직 상태 = 안전거리에서 원거리 집중 딜
- **동시 공격 필요 패턴**: 두 타겟 동시 파괴 시 페이즈 전환 (혼자선 불가능)
- **파트너 부활 요소**: 일부 보스가 다운된 파트너를 "잡아감" → 반드시 구출 필요

## 플레이어가 사랑하는 요소

1. **협동 밸런싱**: 두 캐릭터가 각자 빛나는 순간이 교차되어 지루하지 않음
2. **비대칭 재미**: Ace는 근접 타이밍 게임, Nina는 조준 정확도 게임 → 다른 플레이 경험
3. **온라인 넷코드**: 롤백 넷코드로 인터넷 연결 상태에서도 쾌적한 온라인 협동
4. **픽셀아트 퀄리티**: 각 월드마다 뚜렷한 테마 (공장/자연/우주 등)
5. **파워업 시너지 탐구**: 런마다 새 조합 발견의 재미

## OnionCat 직접 적용 포인트

### 1. 비대칭 협동 설계 원칙 (가장 핵심)

30XX에서 검증된 법칙:
```
"각 캐릭터가 '내가 빛나는 순간'을 번갈아 가져야 한다"
- Ace가 근접 필수 구간 → P1(고양이) 담당
- Nina가 원거리 필수 구간 → P2(양파) 담당
- 두 캐릭터 동시 기여 구간도 반드시 포함
```

### 2. 공유 자원 설계

```csharp
// SharedResources.cs
public class SharedResources : MonoBehaviour
{
    public static int SharedGold { get; private set; }
    public static int SharedSouls { get; private set; } // OnionCat의 영혼 화폐

    public static bool TrySpend(int amount)
    {
        if (SharedGold >= amount)
        {
            SharedGold -= amount;
            OnGoldChanged?.Invoke(SharedGold);
            return true;
        }
        return false;
    }
    public static event System.Action<int> OnGoldChanged;
}
```

### 3. 부활 시스템 (OnionCat 응용)

OnionCat은 두 플레이어가 한 몸을 공유하므로 "부활" 개념보다:
- **조작권 강제 전환**: P1이 행동 불능 상태(기절) → P2만 조작 가능 상태
- **역할 스왑**: 특정 상태에서 임시로 P2가 이동도 제어하는 긴급 모드
- 구현 참고: 30XX의 `ReviveTarget` 컴포넌트 개념 → OnionCat의 `IncapacitatedState`

### 4. 보스 협동 필수 패턴 (직접 벤치마크)

```
보스 패턴 설계 체크리스트 (30XX 기준):
[ ] P1(근접) 전용 취약 타이밍 최소 1개
[ ] P2(원거리) 전용 취약 타이밍 최소 1개
[ ] 두 플레이어 동시 역할 필요 타이밍 최소 1개
[ ] 피해야 하는 판정을 각자 다른 방향으로 분산
```

### 5. 방 분기 선택 UI (30XX 월드맵 방식)

- 각 층에서 다음 방 유형을 미리 보여주고 선택 (위험 vs 안전 vs 상점)
- OnionCat 적용: 방 진입 전 문 위에 아이콘 표시 (전투/상점/이벤트)
