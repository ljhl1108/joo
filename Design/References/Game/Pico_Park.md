## 핵심 메카닉

### 강제 협동 설계 철학
Pico Park의 핵심은 "두 플레이어가 동시에 특정 행동을 해야만 진행 가능한" 퍼즐 설계다. 한 명이 아무리 잘해도 단독으로는 절대 클리어 불가.

**대표 강제 협동 패턴:**
- **무게 스위치**: P1이 버튼을 밟고 있어야 P2가 통과 가능
- **열쇠-자물쇠 동기화**: 두 플레이어가 각각 다른 위치의 스위치를 동시에 누름
- **공 패스**: 한 플레이어가 공을 잡아 다른 플레이어에게 던져야 골인
- **로프 연결**: 두 플레이어가 로프로 연결된 상태로 이동하면 자동으로 협력 동선 생성
- **발판 제공**: P1이 P2를 밟고 점프해 높은 곳 도달

### 단순한 컨트롤 + 복잡한 협력
- 기본 조작: 이동 + 점프만 존재 (공격 없음)
- 단순한 조작이기 때문에 협동 실패 원인이 100% "커뮤니케이션 부재"임
- 플레이어 간 의사소통이 메카닉 자체

### 가시적 실패 → 웃음 유발 설계
- 한 명이 실수하면 모두가 죽음
- 죽을 때 작은 도트 캐릭터들이 터지는 연출
- 실패가 좌절이 아닌 웃음으로 귀결되는 그래픽/연출 선택

## 협동 요소 분석

### "대화 없이 행동으로 협력 유도"
Pico Park은 음성 채팅이나 텍스트 없이도 퍼즐이 자연스럽게 협력을 유도한다.
- 퍼즐 구조가 "지금 뭘 해야 하는지"를 시각적으로 즉시 알려줌
- 플레이어가 스스로 역할 분담을 발견하게 함

### 역할 비대칭 없음 → 대등한 파트너십
- 두 플레이어가 동일한 능력치를 가짐
- 역할이 고정되지 않고 상황에 따라 누가 어떤 역할을 할지 유동적으로 결정

### 압박감 조절
- 스테이지가 짧아서 실패 후 재시도 부담이 낮음
- 타이머 없음 → 서두를 필요 없이 협력 계획 수립 가능
- 단, 일부 스테이지에서 이동하는 장애물이 자연스러운 압박감 생성

---

## 플레이어들이 사랑하는 이유

1. **웃음 유발 협동**: 실패가 재미있고 성공이 뿌듯한 감정 롤러코스터
2. **접근성**: 게임 경험이 없는 사람도 조작이 쉬워서 같이 할 수 있음
3. **짧은 스테이지**: 집중력이 끊기기 전에 클리어 (1~3분/스테이지)
4. **즉각적 리트라이**: 죽으면 바로 재시작, 흐름이 끊기지 않음
5. **무언의 소통**: 말하지 않아도 서로의 의도를 읽는 재미

## OnionCat 적용 포인트

### 1. 강제 협동 방 디자인 원칙
OnionCat의 "두 플레이어가 한 몸을 공유"하는 컨셉에 Pico Park의 강제 협동 설계 원칙을 적용:
- **P1(Cat)이 근접 공격으로 스위치를 부수는 동안 P2(Onion)가 원거리로 다른 스위치를 동시에 맞혀야 문이 열리는 방**
- 한 플레이어가 두 스위치를 동시에 처리하는 것이 물리적으로 불가능하게 설계

### 2. 실패의 웃음 설계
Cat+Onion이 한 몸이므로 한 명의 실수가 즉각적으로 전달됨 → 이 특성 활용:
- 피격 시 화분이 흔들리고 Onion이 흙을 흘리는 코믹한 연출
- 사망 시 화분이 산산조각나는 과장된 애니메이션 (좌절 방지)

### 3. 동시 입력 메카닉
특정 방 요소(보스 취약 포인트, 특수 문 등)를 "P1과 P2가 정확히 같은 타이밍에 각자의 공격을 명중"시켜야 활성화하는 패턴:
```csharp
public class SyncTrigger : MonoBehaviour
{
    private bool _p1Ready;
    private bool _p2Ready;
    private float _syncWindow = 0.3f; // 0.3초 이내 동시 입력

    public void RegisterHit(int playerId)
    {
        if (playerId == 1) { _p1Ready = true; StartCoroutine(ResetAfterWindow(1)); }
        if (playerId == 2) { _p2Ready = true; StartCoroutine(ResetAfterWindow(2)); }
        if (_p1Ready && _p2Ready) Activate();
    }
}
```

### 4. 역할 전환 허용 설계
Pico Park의 "역할 비대칭 없음"과 달리 OnionCat은 의도적으로 역할이 다르지만, 특정 상황에서는 P2 Onion이 몸체를 좌우로 조종해 P1 Cat의 슬래시 방향을 바꾸는 "간접 컨트롤" 제공 → 대등한 파트너십 느낌 강화

### 5. 짧은 방 & 즉각 리트라이
Pico Park의 짧은 스테이지 철학 채택:
- 방 하나당 클리어 시간 목표: 20~60초
- 사망 시 방 처음부터 즉각 재시작 (페이드아웃 최소화, 0.3초 이내)
