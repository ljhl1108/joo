## 핵심 시스템

### 장비 시스템 (아이템이 정체성을 결정)
- **장비 슬롯**: 무기 · 갑옷 · 반지 2개 · 아티팩트 · 잡동사니 · 허리띠
- **장비 강화**: +1~+5 단계. 강화석(`Scroll of Upgrade`)이 런 핵심 자원
- **장비 식별**: 아이템은 처음엔 "???" — 사용하거나 감정 스크롤로만 진짜 이름·효과 확인. 리스크와 발견의 재미를 동시에 줌
- **저주(Curse)**: 강화를 잘못 하면 저주가 걸려 음수(-1~-5) 강화치. 저주 해제 스크롤 필요 → "이 무기를 쓸까 버릴까?" 딜레마

### 세트 대신 시너지 조합
Shattered PD는 별도의 세트 시스템 대신 **특성 조합**으로 효과를 복합:
- **무기 인챈트 + 갑옷 강화 + 반지 효과**가 서로 곱연산처럼 시너지
- 예: `Grim Enchant` (HP 25% 이하 적 즉사) + `Ring of Furor` (공격 속도 +) + `Amok Wand` = 중후반 특화 빌드
- 빌드 다양성의 원천: 아이템마다 1~2개의 특성이 서로 얽혀 예상치 못한 조합이 나옴

### 캐릭터 서브클래스 시스템
- **기본 직업 4개**: 전사 / 마법사 / 악당 / 사냥꾼
- **서브클래스**: 직업마다 2개 분기, 던전 중반에 선택 → 패시브 능력 + 새 스킬 부여
- **서브클래스 선택의 무게**: 잘못 고르면 빌드 방향과 엇갈려 런이 힘들어짐. 플레이어가 런 초반부터 "이번엔 어떤 방향으로 갈까?" 생각하게 함

### 도전 시스템 (Challenges)
- 런 시작 전 최대 6개 도전 조건 선택 (예: "마법 아이템 없음", "영구 저주", "굶주림 2배")
- 도전을 더 많이 선택할수록 고득점 → **자발적 난이도 설계**
- 완전히 별도의 게임 모드 아닌데도 베테랑에게 계속 도전감 제공

### 레벨 구조
- **25층 던전 5구역**: 하수도 → 감옥 → 동굴 → 도시 → 홀
- 구역 끝마다 **보스** 1명 + 보스 방 전 체크포인트 역할의 상점
- 각 구역은 테마 다른 타일셋 + 적 + 환경 함정

### 배고픔 / 자원 압박
- HP는 자연 회복되지만 **음식이 없으면 굶주림 피해** → 자원 관리가 던전 클리어의 핵심
- 수동적 "시간 지나면 회복" 없음 → 매 방 매 전투가 소모전

## 협동 요소
해당 없음 — 1인 게임. 그러나 **커뮤니티 빌드 공유 문화**가 강해서 Reddit에 "이번 빌드로 깼다!" 스레드가 많음. 이것이 사실상 비동기 사회적 경험.

## 플레이어가 좋아하는 것

1. **아이템 발견의 재미**: 처음엔 모르는 아이템 → 식별 후 "이거 대박인데?" 순간
2. **빌드 상상력**: 런마다 전혀 다른 조합이 가능, "이번 런은 X 중심 빌드로"라는 의도 설계 가능
3. **허용적 실수 처리**: 실패해도 배움이 있음. 시스템이 복잡하지만 단순한 조작
4. **1인 개발자의 꾸준한 업데이트**: 팬덤과 개발자 소통이 활발 → 신뢰감

## OnionCat 적용 포인트

### 1. 장비 식별 / 미지의 재미 (아이템 이름 숨기기)
- OnionCat은 현재 카드 선택 시 아이템 이름·효과 전부 보임
- **도전 런(챌린지 모드)에서 에픽 이상 장비는 이름 가림 — 장착 후 확인** 방식 추가 가능
- 구현: `GearCardUI`에 `obscureName` 플래그 + `GearScreen`에서 장착 후 해제

### 2. 강화 딜레마 설계 (레벨업 vs. 씨앗)
- OnionCat의 씨앗은 분해 + 상점에서 쓰임
- SPD처럼 **강화 vs. 다른 용도 딜레마**: 씨앗을 써서 장비를 레벨업하면 좋지만, 같은 씨앗으로 상점에서 희귀 장비를 살 수도 있음
- 이미 어느 정도 존재하는 구조 — SPD는 이 딜레마가 매 층마다 발생하게 설계함

### 3. 캐릭터 서브클래스 → 할퀴기 변형 선택 타이밍
- SPD는 중반에 서브클래스를 **선택하는 행위** 자체가 이정표 역할
- OnionCat의 `ClawStyle` 변형 선택도 "특정 방을 클리어하면 선택지 팝업"으로 만들면 런에 방향성 부여 이정표가 생김
- 지금은 장비에서 자동으로 바뀌는데, 명시적 "선택 이벤트"를 추가하면 기억에 남는 순간이 됨

### 4. 도전 조건 시스템 (Challenge Modifiers)
- SPD의 "조건 켜기" 방식은 `Custom_Run_Modifier_System.md`에서 이미 연구됨
- OnionCat에서: 런 시작 전 "씨앗 없음 런" / "보스만 나오는 런" / "고양이 솔로(양파 스킬 잠금)" 등
- **장기 리플레이어빌리티 핵심**: 클리어한 사람에게 새 의미를 주는 가장 저비용 방법

### 5. 아이템 저주 → 등급 하락 기믹
- SPD의 저주는 좋은 아이템에 단점을 추가
- OnionCat에서 응용: 분해 때 가끔 **"저주받은 효과"가 같이 붙어 나오는 장비** 등장 → 강하지만 단점 있음(예: "공격력 +30%, 하지만 씨앗 수집 불가") 
- 이런 리스크-리워드 아이템은 베테랑만 선택하는 고위험-고수익 플레이 공간을 만듦

### 6. 구역별 환경 압박
- SPD는 구역마다 환경 기믹이 다름 (독 액체 바닥, 어둠 속 전투 등)
- OnionCat도 스테이지마다 **환경 기믹 1개씩** 있으면 좋음: 정원 = 식물 성장 빠름, 탑 = 중력(점프 낮음), 늪 = 바닥이 젖어 있음
- 현재 임시 색 오버레이 + 적 교체만으로 스테이지 차별화 중 — SPD처럼 플레이 방식 자체를 바꾸는 환경이 있어야 진짜 다른 경험
