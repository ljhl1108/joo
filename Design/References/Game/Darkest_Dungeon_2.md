## 핵심 시스템

### 스테이지코치 로드 트립 구조
- 1편의 "마을 거점 + 던전 반복" 구조 대신 **한 번의 런 = 한 번의 여정(Road Trip)** 구조
- 플레이어가 스테이지코치를 조종해 바이옴(지역)을 이동
- 각 바이옴은 **분기 도로(Forked Road)**로 구성: 교차로마다 경로 선택
- 경로 위에 **노드(Node)** 배치: 전투, 상점, 병원, 캠프, 이벤트 등
- 노드 사이 구간: 스테이지코치를 직접 운전하며 장애물 회피 + 아이템 수집 (단순 미니게임)

### 파티 시스템 (4인 고정)
- 런 시작 시 영웅 4명을 선택 → 이 4명으로 런을 끝내야 함
- 각 영웅은 줄 위치(Position 1~4)에 따라 사용 가능한 스킬이 다름
- 포지션 교체가 전술의 핵심

### 어피니티(Affinity) 시스템 — 관계가 전투력을 바꾼다
- 영웅 간 **관계 게이지**가 쌓임: 긍정적(Bond) / 부정적(Tension)
- Bond: 전투 중 시너지 스킬 발동, 스트레스 공유 감소
- Tension: 서로 방해하는 행동 유발, 불복 이벤트 발생 가능
- **캠프**에서 대화·식사·교류 이벤트로 관계를 조절

### 스트레스 & 희망(Hope) 시스템
- 1편의 퀴르크(Quirk) 시스템이 **희망/절망 척도**로 단순화
- 스트레스가 쌓이면 절망 → 전투 디버프, 도주 위험
- 반대로 승리 시 희망 증가 → 버프

### 메타 진행 — 캔들(Candle)
- 런 실패 시 **캔들** 획득
- 캔들로 영웅 새 경로(Path) 잠금 해제, 시작 버프, 아이템 잠금 해제
- 각 영웅마다 독립적인 Path: 런 시작 전 해당 Path 선택 → 스킬·스탯 변형

### 유물(Relic) 시스템
- 런 중 유물을 수집해 전투 스타일을 형성
- 유물 간 시너지 조합이 빌드의 핵심 재미

## 플레이어가 좋아하는 점

| 요소 | 이유 |
|------|------|
| 영웅 관계 시스템 | 파티 구성이 단순 수치 조합을 넘어 드라마틱한 순간을 만듦 |
| 분기 선택의 무게 | "어느 길이 더 위험한가"를 매 교차로마다 고민 |

## 비판 받는 점

- 스테이지코치 조종 미니게임이 단조롭고 어색함
- 1편 팬들은 거점 관리 메타게임 제거를 아쉬워함
- 스트레스 시스템이 덜 정교하다는 의견

## OnionCat 적용 포인트

### 1. "런 = 여정" 서사 구조
- OnionCat도 방들을 단순 나열이 아니라 **여정의 챕터**로 프레임을 잡을 수 있음
- 예: 방 사이 "이동 이벤트" 텍스트 팝업으로 세계관 전달 (Hades의 교신 대사 방식)

### 2. 분기 경로 선택 UI
- 현재 `DungeonManager`의 방 풀 무작위 배치에 **분기 지도 UI** 추가 가능
- 플레이어가 다음 방 종류(전투 중점, 상점, 고난이도 + 보상)를 미리 선택하게 함
- 기술 참고: `Design/References/Tech/InRun_Branch_Map_System.md`

### 3. 두 캐릭터 관계 게이지
- 고양이와 양파가 **협력 수치(Synergy Gauge)**를 공유
- 잘 싸우면 증가 → 합동기 게이지로 직결 (이미 구현된 협력 콤보 시스템과 연결)
- 나쁜 상황(한 명 사망 근처, 연속 피격)에서 수치 감소 → 특수 네거티브 이벤트

### 4. 캔들형 메타 진행
- 런 실패 시 **메타 포인트** 획득 → 영구 잠금 해제 (새 스킬, 새 적, 새 방 타입)
- 현재 `GameManager.Run(RunData)` 체계에 `MetaProgressionData` 추가
- `ScriptableObject` 잠금 해제 조건 + `Meta_Progression_System.md` 참고

### 5. 포지션 의존 어빌리티
- OnionCat의 근거리(고양이) / 원거리(양파) 분업이 이미 포지션 의존적
- 적 중 "전방 캐릭터만 공격 가능 / 후방 캐릭터만 공격 가능" 패턴 추가 가능
