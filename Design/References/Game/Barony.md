## 핵심 메커닉

### 협동 플레이 구조
- 최대 4인 온라인 협동 플레이
- 각 플레이어가 독립된 캐릭터로 행동하되 **역할 전문화**가 자연스럽게 발생
- 공유 자원 없음 → 각자 아이템 루팅, 그러나 생존은 팀 단위로 평가
- 퍼머데스: 동료가 죽으면 귀신(ghost) 상태로 전환, 살아있는 팀원이 부활 아이템을 사용해야 복귀 가능

### 직업(Class) 시스템
| 직업 | 역할 | 핵심 메커닉 |
|------|------|-------------|
| Warrior | 근접 탱커 | 방어구 내성, 근접 공격력 ↑ |
| Ranger | 원거리 딜러 | 활·크로스보우 숙련, 독화살 |
| Wizard | 마법 딜러 | 마나 기반, 광역 주문 |
| Healer (Cleric) | 힐러 | 치유 주문, 언데드 특화 |
| Rogue | 스텔스 딜러 | 백어택, 함정 해제 |

→ **역할 전문화가 생존 필수**: Warrior만 큰 적과 붙고, Ranger는 뒤에서 지원

### 적 약점 시스템
- **언데드 적**: 클레릭 성스러운 공격에 추가 피해, 일반 물리 공격은 감소
- **갑옷 적**: 관통 무기(화살 일부)로 갑옷 무시 가능, 망치류로 방어력 감소
- **마법 적**: 물리 공격만 유효, 마법 반사 쉴드 보유
→ "어떤 적에게 누가 붙어야 하는가"를 팀이 실시간으로 판단해야 함

### 함정 & 환경 위험
- 바닥 함정, 낙하 구덩이, 자동 발사 대포 등
- 팀원이 앞에서 함정 감지·해제(Rogue), 나머지는 뒤에서 대기
- 협력 없이는 필연적으로 사망

### 영구 진행과 런 구조
- 층마다 무작위 던전 생성 (30층 + 최종 보스)
- 층 내 상점, 신사, 비밀 방 존재
- 아이템 저주: 장착 전 식별 필요 → 팀원과 정보 공유가 중요

## 플레이어들이 사랑하는 것

1. **진정한 협동 긴장감**: 팀원이 죽으면 귀신이 되어 지켜봐야 하는 공포 → 부활 아이템을 위해 위험을 감수하는 선택
2. **역할 분업의 자연스러운 발생**: 규칙으로 강제하지 않지만 살아남으려면 자연스럽게 Warrior가 앞서고 Healer가 뒤에 서게 됨
3. **정보 비대칭 협력**: 다른 플레이어가 발견한 아이템 정보를 공유해 최선의 선택
4. **예측 불가능한 던전**: 매 런마다 다른 레이아웃, 적 배치, 아이템

## OnionCat 적용 포인트

### 1. 역할 강제 없이 역할 발생
Barony는 규칙으로 "Cat=근접, Crop=원거리"라고 강요하지 않음에도 클래스 특성상 자연스럽게 분업됨. OnionCat도 비슷한 접근:
- Cat은 대시+무적이 있어 적에게 달려드는 것이 자연스러움
- Crop은 마우스 조준이 정밀해 원거리 타격이 더 유리
- 규칙이 아닌 **능력의 특성**으로 역할을 유도

### 2. 적의 약점 타입이 협력을 강제
Barony의 언데드=클레릭 필수 구조처럼:
- OnionCat에서 "근접만 데미지 적" vs "원거리만 데미지 적"을 더 명확하게 구분
- 플레이어가 적을 보자마자 "이건 내 담당" / "이건 네 담당"을 즉각 인식하도록 시각 신호 강화 (색상, 실드 이펙트)

### 3. 부활 메커닉의 감정적 힘
Barony의 ghost 부활 시스템이 팀 유대감을 강화하듯:
- OnionCat의 Crop은 Cat HP 0 시 잠깐 독립 행동(물 뿌리기 부활 시퀀스) 구현
- "내가 파트너를 살렸다"는 경험이 협동의 만족감을 극대화

### 4. 함정 방 분업
- "Cat이 앞서 함정 트리거, Crop이 화살로 원격에서 적 처리" 형태의 방 설계
- 두 플레이어가 물리적으로 다른 역할을 하는 공간 구성이 On onCat에 적합

### 5. 아이템 정보 공유의 긴장감
Barony의 저주 아이템 식별 시스템처럼:
- 업그레이드 선택 시 Cat/Crop 중 누구에게 더 유리한지 두 플레이어가 논의하도록 설계
- 협동 업그레이드 선택 UI에서 "Cat용 / Crop용 / 공용" 카테고리 분류
