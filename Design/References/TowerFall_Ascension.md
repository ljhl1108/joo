## 핵심 메커닉

### 1. 화살 경제 (Arrow Economy)
- 최대 3발의 화살만 소지 가능
- 화살은 맵에 박혀 있음 → 회수해야 재사용
- **자원 관리** + **위치 파악** + **전술 이동**이 통합

### 2. 극도로 단순한 조작
- 방향키 이동, 점프, 공격(화살 발사), 회피 대시 4가지
- 단순 조작 → 극도로 깊은 심도 (Depth from simplicity)
- **화살 방향 조절**: 위 누른 채 발사 = 위쪽 화살, 앉아서 = 무릎 화살

### 3. 관용적 히트박스 (Forgiving Hitboxes)
- 화살이 플레이어를 아슬아슬하게 지나가도 피격 처리 안 됨
- **"느껴지는 공정함"** → 플레이어가 억울함을 덜 느낌
- 타이밍 기반 콤보 → 방패로 화살 막기 가능

### 4. 협동 Trials 모드
- 1~2인이 웨이브형 적 처치
- 협동 특화: 화살 아끼기 위해 근접 밟기로 처치 유도
- 역할 분담: 한 명이 어그로, 다른 명이 저격

## 협동 요소 분석

### 동기화된 위험과 보상
- 공유 목숨 → 한 명의 실수가 전체에 영향
- 화살 부족 상황 → 서로 지원 또는 혼자 해결
- **압박감을 나누는 구조** → 협동의 당위성 자연 발생

### 공간 활용 협동
- TowerFall 맵은 작음 → 좁은 공간에서의 역할 분담 필수
- OnionCat처럼 "같은 화면에 두 플레이어" → 시야 공유 긴장감

### 읽기 쉬운 상태 표시
- 화살 개수가 캐릭터 아이콘 옆에 실시간 표시
- 체력 하트가 HUD 상단에 명확하게 표시
- **"지금 우리 상황이 어떤지" 1초 안에 파악 가능** → 협동 의사결정 속도 향상

## "게임 느낌(Game Feel)" 철학

TowerFall은 인디 게임계에서 가장 완성도 높은 "게임 느낌"으로 평가받음.

### 핵심 원칙 (Matt Thorson 인터뷰 기반)
1. **모든 것을 단순하게, 깊게** — 4가지 동작만으로 무한한 표현
2. **명확한 읽기** — 적의 다음 행동이 0.5초 전에 예측 가능
3. **즉각적 반응** — 입력 → 반응 레이턴시 최소화 (<1프레임)
4. **공정한 죽음** — 죽을 때 "내 실수"라는 느낌 주기
5. **리듬감** — 화살 발사 → 이동 → 회수 → 발사 사이클이 리드미컬

## OnionCat 적용 포인트

### 1. 자원 경제 도입 가능성
- 고양이 슬래시: 쿨다운(시간 자원)
- 양파 탄환: 발사 횟수 제한 or 차지 게이지 (자원)
- **자원 관리 + 역할 협동**이 맞물리면 의미 있는 협동 발생

### 2. "공정한 히트박스" 우선
- 픽셀아트 게임에서 히트박스는 스프라이트보다 작게
- 특히 투사체 히트박스는 매우 너그럽게 → 억울함 방지
- 이미 `Hitbox_Design.md`에서 다뤘지만 TowerFall이 표준 사례

### 3. 협동 읽기 쉬운 HUD 설계
- 두 캐릭터의 상태(체력, 스킬 쿨다운)를 화면 한 쪽에 몰아서 표시
- 한 눈에 "지금 어떤 상태인지" 파악 가능한 UI 구조 필수
- 특히 OnionCat는 한 몸이므로: 공유 체력 + 각자 스킬 상태 표시

### 4. "명확한 예고" 시스템
- TowerFall 적들은 공격 전 0.5초 경직 → 예측과 대응 가능
- OnionCat 적 설계에 **전신 경직(Wind-up) 애니메이션** 필수
- `Enemy_Telegraph_System.md`와 연계

### 5. 1인 개발로 완성한 사례
- Matt Thorson 1인 개발, Madeline(Celeste 동일 개발자)과 협업
- 아트 스타일: 16색 팔레트 제한 → 일관성 + 작업량 감소
- **작은 범위 + 높은 완성도** → 초보 개발자에게 귀감

## 플레이어들이 사랑하는 것

1. **즉각적 반응성** — 무슨 키를 눌러도 즉시 반응
2. **아슬아슬한 생존** — 화살 0발 상태에서의 역전
3. **공유 경험** — 좁은 공간 협동의 긴장감
4. **반복 플레이** — 3분 한 판, 질리지 않는 루프
