## 캐릭터 (01_Characters)

- **고양이 클래스 분기** — Rogue Genesia 참고: 런 시작 전 고양이 스타일 선택 ("돌격형 고양이"는 슬래시 범위 +30%, "수비형 고양이"는 기본 체력 +30%). 클래스 패시브는 `ScriptableObject`로 구현, 런 시작 시 `PlayerStats`에 주입.
- **양파 성장 단계 시각화** — Rogue Genesia 진화 시스템 참고: 업그레이드를 쌓을수록 화분의 양파 스프라이트가 새싹→중간→완숙으로 변화. `PlayerStats`의 업그레이드 누적 수에 따라 Animator에서 스프라이트 스왑.
- **협력 클래스 조합 보너스** — 고양이 "스피드형" + 양파 "저격형" 조합 선택 시 특별 보너스 패시브 해금. 각 클래스 ID 조합을 딕셔너리로 관리, 런 시작 시 체크.

## 적 (02_Enemies)

- **저주 거울 적** — Rogue Genesia의 저주 시스템 참고: 처치 시 플레이어 스탯을 1개 약화시키는 적. "죽이면 손해"라는 역설적 선택지 제공 → 우회 유도로 협력 패턴 다양화.
- **업그레이드 도둑** — 플레이어 다음 업그레이드 선택지를 미리 훔쳐가는 적. 처치 후 되찾거나, 처치 못하면 선택지 1개 감소. 업그레이드 UI의 `PickRandom` 결과를 캐싱해 구현.
- **클래스 카운터 적** — "근접 특화 적"은 Onion 투사체에만 반응, "원거리 특화 적"은 Cat 슬래시에만 피해를 입음. OnionCat의 핵심 협력 필수 메카닉을 강화하는 적 타입.

## 맵 (03_Maps)

- **클래스 룸** — 런 중간에 등장하는 특수 방. 여기서만 클래스 패시브를 교체 가능. 리스크 없이 전략을 바꿀 수 있는 안전 탈출구.
- **저주 제단 방** — Rogue Genesia의 저주 개념 적용: 방 입장 시 "저주 수락 / 거절" 선택. 수락 시 방 내 적 강화 + 보상 증가. 화분에 균열 스프라이트 오버레이로 저주 상태 표시.
- **진화 시험 방** — 특정 조합 업그레이드 조건을 갖춘 플레이어에게만 입장 허용되는 숨겨진 방. 일반 룸과 동일 프리팹이지만 문 잠금 조건을 `UpgradeManager`가 체크.

## 전투 (04_Combat)

- **연계 업그레이드 시너지** — Cat의 "차지 슬래시" + Onion의 "관통탄"을 둘 다 보유 시 **새로운 연계기 해금**: 슬래시 후 1초 내 투사체 발사 시 전방 3방향 관통탄 발사. `UpgradeManager`에서 두 업그레이드 보유 여부를 런타임에 체크.
- **리롤 자원화** — Rogue Genesia 리롤 참고: 씨앗(seed) 아이템이 업그레이드 리롤 화폐로 기능. 적 처치 드롭 or 상자에서 획득. 리롤 비용은 매번 씨앗 1→2→4개로 증가.
- **희귀도별 전투 변화** — 에픽(보라) 업그레이드 이상은 기존 공격 패턴을 완전히 교체. 예: 에픽 슬래시 = 360° 회전 슬래시로 대체. `UpgradeData` 상속 클래스에서 기존 컴포넌트를 Disable하고 새 컴포넌트 Enable.

## 스토리 (05_Story)

- **저주의 기원 설정** — 화분 속 양파는 원래 마법에 걸린 왕족. 저주 때문에 작물 형태에 갇혀 있음. 고양이는 양파의 보호자 겸 파트너. "저주를 함께 풀기 위해 던전을 탐험"하는 동기.
- **클래스 스킨 = 과거 기억** — 클래스 변경 시 등장하는 짧은 비주얼 노벨: "화전 고양이 기억", "궁수 양파의 기억" 등. 각 클래스 스킨마다 2~3줄 단편 스토리. 대화 시스템 없이 UI 텍스트만으로 구현 가능.
- **진화 업그레이드 = 봉인 해제** — 연계 시너지 해금은 스토리적으로 "두 사람의 유대가 깊어져 봉인된 힘 해방"으로 표현. 진화 시 화면에 짧은 연출(화면 빛남 + 텍스트 팝업) 추가.

## 기술 메모

- **업그레이드/아이템 시스템**: `ScriptableObject` + 상속 구조가 핵심. `UpgradeData.Apply(PlayerStats)`를 오버라이드하는 방식으로 수십 개의 업그레이드를 코드 한 곳에서 관리 가능. 먼저 `PlayerStats` 클래스부터 만들고, 거기서 수정할 수 있는 스탯 변수를 전부 정의하는 것이 선행 작업.
- **빌드 및 배포**: 개발 초반부터 `Build Settings`의 씬 목록을 정리해두는 습관이 중요. WebGL 빌드는 `Run in Background` ON + 게임패드 한계 인지. 첫 외부 공개는 itch.io 비공개 링크 → 지인 5명 플레이테스트가 가장 효율적인 루프.
