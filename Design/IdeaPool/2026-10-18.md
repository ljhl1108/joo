## 캐릭터 (01_Characters)

- **고양이 무기 아이덴티티 강화** — Grim Dawn Reaper 무기 참고: 각 고양이 무기가 ClawStyle 교체 외에도 2차 스탯(쿨다운 단축, 이동속도, 대쉬 충전속도 등)에서 개성이 있어야 "이 무기를 들면 이렇게 싸운다"가 명확해짐. 현재 무기별 차이가 ClawStyle에만 집중되어 있다면, 무기별 캐릭터 느낌 차이 강화 필요
- **마법서 레벨업 선택 노드** — The Slormancer 스킬 트리 참고: 마법서가 레벨업(중복 획득)될 때 단순 수치 강화 대신 "산탄 수 +1 vs 쿨다운 -0.5초 vs 관통 추가" 중 선택하는 팝업 UI. 구현 복잡도 높지만 마법서 레벨업이 의사결정 순간이 됨. 후반 작업으로 검토
- **패시브 "발동형" 비중 확인** — Grim Dawn 헌신 시스템 참고: 현재 OnionCat 패시브가 수치 강화(+X%) 위주인지, 조건부 발동형("킥 후 X초 안에 씨앗 명중 시 게이지 +5")이 충분한지 점검. 발동형 패시브는 전투 중 "내가 뭔가 했다"는 즉각 피드백 제공

## 적 (02_Enemies)

- **적 처치 텔레메트리 우선 적용** — 로컬 텔레메트리 참고: `enemy_killed` 이벤트에 `killedBy(Cat/Onion)` 기록 → 고양이 vs 양파 딜 기여율 분석. 고양이가 99%면 양파의 존재감이 약하다는 신호. 5런 데이터만 있어도 밸런스 판단 가능
- **방 클리어 시간 분포 측정** — `room_cleared` 이벤트로 방별 소요 시간 기록 → 평균 30초~2분이 이상적. 특정 방 유형(엘리트/일반/보스)의 클리어 시간 편차가 크면 해당 방 배치 재검토
- **적 세트 시너지 힌트** — Grim Dawn 팩션처럼 "이 방에 등장한 적 조합이 의도적 시너지를 갖는다"는 개념 도입. 예: 방패병 + 원거리 적 조합은 "방패병 뒤에 숨는 원거리" 패턴으로 킥 활용을 강요. 방 배치 설계 시 적 조합 의도를 명시화

## 맵·런 구조 (03_Maps)

- **세트 완성 알림 이정표** — Grim Dawn 세트 마지막 조각 수집 쾌감 참고: 세트 6단계 또는 8단계 완성 시 "세트 완성!" 전용 연출(이펙트 + 효과음). 현재 HUD에서 세트 진행도는 보이지만 "완성"의 클라이맥스 연출이 있는지 확인 필요
- **런 방향 선택의 트레이드오프 강화** — Grim Dawn 팩션처럼, 출구 선택(A축 vs B축)이 단순 보상 유형 차이가 아니라 "이걸 가면 저걸 못 간다"는 장기 방향 선택처럼 느껴지면 좋음. 출구 표식에 현재 보상 축 외에 "이번 런 세트 방향"을 암시하는 UI 추가 검토
- **런 텔레메트리 → 방 난이도 균형 조정** — 로컬 텔레메트리로 "런 1~3방은 HP 손실 거의 없음, 4방부터 급격히 위험"이 확인되면 초반 방 난이도 상향 또는 후반 방 조정 가능. 객관적 데이터 없이는 "느낌"으로만 판단하게 됨

## 전투·협동 (04_Combat)

- **협동 콤보 발생 빈도 측정** — 로컬 텔레메트리 참고: `coop_combo` 이벤트 기록 → 런당 평균 콤보 횟수가 10회 이하면 시스템이 플레이어 경험에 잘 안 보이는 것. 목표치 설정(런당 20~30회?) 후 달성 안 되면 콤보 발동 조건 완화
- **세트 "점프 포인트" 체감 확인** — Grim Dawn 2/4/6피스 단계 설계 원칙 참고: OnionCat 세트의 2/4/6/8단계 보너스가 각 단계에서 "확실히 다른 느낌"인지 실제 플레이로 확인. 8단계 보너스가 6단계 대비 눈에 띄지 않으면 동기 부여 약해짐
- **걷어차기 + 세트 시너지 발동형 효과 아이디어** — 예: "바람 세트 4단계: 걷어차기로 날아가는 적이 벽에 CRASH 시 주변 적들에게 원소 데미지". 걷어차기를 세트 시너지의 트리거로 활용하면 킥이 협동 외에도 세트 빌드에서 의미를 가짐

## 아이템·세트 (05_Items)

- **세트 정체성 한 줄 정의 재검토** — Grim Dawn 세트 설계 원칙 참고: 현재 10개 세트 각각을 "이 세트는 X 전략에 강하다"고 한 줄로 설명 가능한지 점검. 설명이 안 된다면 세트 효과 재설계 필요. 예시: 햇살=원소 누적·속성 시너지 / 바람=이동·회피·대쉬 / 폭풍=협동 콤보 중심 / 뿌리=식물·설치형
- **장비 접사(어픽스) 체계화** — The Slormancer 조합형 접사 참고: 현재 `GearEffect`(발동→행동→대상) 시스템이 있는데, 발동 10개 × 행동 15개 × 대상 5개 조합표가 정리돼 있는지 확인. 빈 조합을 채우면 새 장비 추가가 표에 한 줄 기입으로 가능 (ContentBuilder 방식과 일치)
- **분해 씨앗 피드백 + 효과 목록 등록 연출** — 분해 시 효과가 "효과 갈아끼우기 풀"에 추가될 때 명확한 시각 피드백이 있는지 확인. "새 효과 추가됨: [효과명]" 토스트 알림 1~2초 표시 → 분해의 보상감 강화

## 스토리·메타 (07_StoryMeta)

- **영어 출시 준비 — 지금 당장 시작할 것** — 자동 언어 감지 시스템 참고: 장비 이름/설명/UI 문자열을 ContentBuilder.cs 안에 하드코딩한 채로 두면 나중에 영어 출시 시 수천 줄 수동 수정 필요. 지금부터 `key + korean/english` 구조의 StringTable로 분리 시작 권장. 장비 163개 이름만이라도 외부화
- **플레이테스트 히스토리 문서화** — 로컬 텔레메트리 참고: 5~10런씩 테스트한 결과를 `Guides/Done/`에 날짜별로 기록하는 습관. 텔레메트리 JSON 요약 + 주요 관찰사항. 나중에 "언제 어떤 밸런스 변화가 있었나"를 추적할 수 있음
- **Slormite Studios 얼리 액세스 전략 참조** — 2인팀이 EA로 성공한 패턴: ① 코어 루프가 재미있어야 콘텐츠 부족을 용서받음 ② 개발 로드맵 공개 ③ 버그 픽스 빠르게 ④ 커뮤니티 피드백을 changelog에 반영 표시. OnionCat의 itch.io 출시 시 참고

## 기술 메모

- **로컬 게임 텔레메트리**: 가장 먼저 추가할 이벤트: `room_cleared`(클리어 시간 + 피해 횟수), `player_died`(사망 원인), `gear_acquired`(장비 선택 추이). `#if UNITY_EDITOR || DEVELOPMENT_BUILD` 조건으로 릴리즈에서 자동 제거. `Application.persistentDataPath/Telemetry/run_YYYYMMDD.json`에 저장. Python 3줄로 여러 JSON 합산 분석 가능

- **시스템 언어 자동 감지**: `Application.systemLanguage == SystemLanguage.Korean`이면 한국어, 아니면 영어(기본). `PlayerPrefs`에 저장 → 설정 메뉴에서 재선택 가능. 부트스트랩 씬 `Awake()`에서 2줄만 추가하면 동작. Galmuri11 SDF 폰트는 동적 아틀라스라 커밋 전 `ClearFontAssetData(true)` 필수
