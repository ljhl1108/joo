## 캐릭터 (01_Characters)

- **캣의 대쉬 방향 가중치** — Rotwood 참고: 대쉬 직전 이동 방향이 없으면 마지막 입력 방향으로 대쉬. 입력이 전혀 없었던 경우 캐릭터 기본 facing 방향. 구현 힌트: `_lastMoveDir` 캐싱.
- **어니언의 조준 피드백 레이어** — 공유 캐릭터 아키텍처 참고: P2가 마우스/스틱으로 조준 중일 때 조준선(Dotted Line) 이나 Aim Arc를 Onion 머리 부분에 렌더링. P1 이동과 독립으로 동작해야 함. 구현 힌트: `LineRenderer` 또는 도트 스프라이트 배열.
- **화분(Flowerpot) 표정 시스템** — Crawl의 '캐릭터 개성' 참고: 어니언이 피격될 때 화분이 울고, 패리 성공 시 화분이 반짝임. 별도 SpriteRenderer 컴포넌트로 표정 시트 교체. 구현 힌트: `Animator`의 Sub-Layer로 분리.

## 적 (02_Enemies)

- **비대칭 약점 표시 아이콘** — Crawl 참고: 근접에만 약한 적은 칼 아이콘, 원거리에만 약한 적은 씨앗 아이콘을 체력바 옆에 표시. 플레이어가 보지 않아도 즉시 파악. 구현 힌트: `EnemyData` ScriptableObject에 `WeaknessType` 열거형 필드.
- **Rotwood식 타이밍 적** — 공격 직전 '예비 동작(telegraph)'이 0.3~0.5초 있는 적. 이 타이밍에 어니언이 패리하면 방어 성공, 캣이 대쉬하면 회피. 구현 힌트: `EnemyAttackState`에서 `TelegraphDuration` 코루틴 후 실제 히트박스 활성화.
- **군집 적 + 개인 약점** — Crawl의 Haunt 팀처럼, 3~5마리 군집 이동하지만 개체마다 근접/원거리 약점이 다름. 플레이어가 자연스럽게 역할 분담하게 유도. 구현 힌트: `FlockingEnemy` 스크립트에 개별 `WeaknessType` 랜덤 배정.

## 맵 (03_Maps)

- **방 입장 컷씬 생략 옵션** — Rotwood 참고: 방 전환 속도가 빠를수록 플레이 리듬이 살아남. 문 진입 → 즉시 카메라 이동 → 적 스폰. 페이드 전환 대신 카메라 슬라이드(0.3초)로 충분. 구현 힌트: Cinemachine 타깃 전환 + `m_Lens.FieldOfView` 미세 줌인.
- **역할 특화 단서 방** — Crawl의 정보 비대칭 참고: 한 방은 어니언만 볼 수 있는 원거리 스위치, 다른 방은 캣만 진입 가능한 근접 구역. 협력 없이는 완전 클리어 불가. 구현 힌트: `TriggerZone` 태그로 특정 플레이어 입력만 반응.
- **보스 전 Canteen 방** — Rotwood 참고: 보스 직전 상점/휴식 방 삽입. 긴장 완화 + 보급. 레이아웃: 좌측 상점 NPC, 우측 체력 회복 꽃밭(밟으면 소량 회복). 구현 힌트: 방 타입 `RoomType.Canteen` 별도 프리팹.

## 전투 (04_Combat)

- **4단계 피드백 파이프라인** — Rotwood 참고: 적 피격 시 ①히트스톱 0.08초 → ②파티클 스폰 → ③카메라 진동 0.1초 → ④넉백 적용. 이 순서를 `HitFeedbackSequencer` 단일 컴포넌트로 묶어 모든 공격에 재사용. 구현 힌트: `Time.timeScale` 조작 대신 `Physics2D.simulationMode` 교체 또는 단순 `WaitForSecondsRealtime`.
- **패리 성공 시 역전 공격** — Crawl의 역할 교체 쾌감 참고: 어니언이 패리 성공 → 일정 시간 적이 스턴 + 투사체 반사. 동시에 캣에게 '역습 타이밍 알림' UI(플래시 이펙트). 구현 힌트: `ParrySuccessEvent` → CatController 구독 → `FlashIndicator` 코루틴.
- **비대칭 업그레이드 선택** — Rotwood 클래스별 업그레이드 참고: 런 중 업그레이드 선택 시 "Cat 전용 / Onion 전용 / 공유" 세 카테고리로 분류. P1과 P2가 각자 관련 카드에 반응하도록 카드 테두리 색상 구분. 구현 힌트: `UpgradeData.UpgradeTarget` 열거형 (Cat, Onion, Shared).

## 스토리 (05_Story)

- **화분의 기억** — Crawl의 유령 내러티브 참고: 죽은 어니언의 '전 생(previous run)'이 유령 형태로 나타나 힌트 대사 제공. 런 기반 영구 데이터(처치한 보스 이름 등)를 저장해 다음 런에 대사에 반영. 구현 힌트: `PlayerPrefs`에 보스 이름 저장 → 대사 풀에서 해당 보스 언급 대사 우선 출력.
- **Rotwood 풍 어두운 동화** — Rotwood의 썩어가는 숲 세계관 참고: 어니언의 출신지 = '시들어가는 식물 왕국'. 각 층마다 그 왕국이 파괴된 과거 조각을 발견 (환경 스토리텔링). 구현 힌트: 특정 방에 `StoryPropController` 배치 — 상호작용 시 텍스트 팝업.
- **두 플레이어의 대화** — 공유 캐릭터 아키텍처의 '두 의식이 하나의 몸' 참고: 이동 중 Cat과 Onion이 짧게 속삭이는 대사("앞에 뭔가 있어" / "봐, 씨앗 쏠게"). 구현 힌트: `IdleDialogueTrigger` — 일정 시간 전투 없으면 랜덤 대사 출력 (TMP_Text 페이드 인/아웃).

## 기술 메모

- **2인 공유 캐릭터 시스템**: 핵심은 **단일 Rigidbody2D + 이동 소유권(MoveAuthority) 패턴**. 두 Controller가 velocity를 직접 쓰지 않고 `SharedBodyLocomotion`에 위임해야 한다. 대쉬 중 Onion 입력은 방패/조준만 허용하고 이동에 개입하지 않아야 떨림이 사라진다. 오늘 당장 `SharedBodyLocomotion.cs` 스크립트부터 작성 시작 가능.

- **컨트롤러 페어링 화면**: `PlayerInputManager`의 `Join Behavior: Join Players When Button Is Pressed` 설정 하나면 "Press any button" 흐름이 자동 처리된다. 씬 전환 시 **반드시 `DontDestroyOnLoad`** 처리해야 PlayerInput이 게임플레이 씬에도 살아남는다. 먼저 LobbyScene을 독립 씬으로 만들고, GameplayScene에서 `FindObjectsByType<PlayerInput>()` 로 찾아 컨트롤러에 연결하는 흐름을 잊지 말 것.
