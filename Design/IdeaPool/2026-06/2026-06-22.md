## 캐릭터 (01_Characters)

- **가젯 슬롯 시스템** — Sparklite 참고: Cat과 Crop이 각자 "보조 가젯" 슬롯 1개씩 보유 → 런 중 발견하는 가젯(폭탄/방패/부스터)으로 교체 가능 → 같은 캐릭터라도 매 런 다른 플레이 스타일 형성
- **공생 진동 피드백** — Controller Rumble 참고: Cat이 피격받으면 P1 컨트롤러 강진동 + P2 컨트롤러 약진동 (같은 몸이니까) → 물리적 피드백으로 "공유 몸통" 테마 강화
- **장인 고양이 설정** — Sparklite Ada(기계공) 참고: Cat을 단순 전사가 아닌 "마을 대장장이 고양이"로 설정 → 근접 무기가 공격용이 아닌 정비 도구의 응용이라는 설정 추가

## 적 (02_Enemies)

- **웨이브 2단계 적** — Enemy Spawner 참고: 방 진입 시 1파 잡몹 등장 → 전멸 후 5초 뒤 2파로 강화 적 소환 → 플레이어가 "아직 안 끝났다!"를 경험, 방 클리어 박진감 상승
- **도구 약점 가드** — Sparklite 보스 약점 참고: 특정 적은 몸 앞쪽에 방패를 들고 있어 원거리 차단 → Cat이 대시로 뒤로 돌아가 근접 공격해야만 처치 가능 → Crop이 시선 유도, Cat이 후방 타격하는 협동 플레이 강제
- **스폰 경고 이펙트** — Wave System 참고: 스포너가 활성화될 위치에 0.5초 전 경고 마커(붉은 원) 표시 → 플레이어가 스폰 위치를 예측하고 포지셔닝 결정 → 긴장감 + 전략성 동시 부여

## 맵 (03_Maps)

- **Disruption 테마 방** — Sparklite Disruption 참고: 일부 방은 "지각변동" 상태로 30초 후 레이아웃이 바뀜 → 제한 시간 내 적 전멸 또는 탈출 강요 → 긴박한 웨이브 방 변형
- **바이옴별 스포너 특성** — Sparklite 5바이옴 참고: 숲 바이옴 방은 수풀 뒤 스폰 포인트(시야 차단), 광산 바이옴은 천장에서 낙하 스폰 → 바이옴마다 스폰 연출이 달라 탐험 신선도 유지
- **금고(Vault) 방** — Sparklite Vault 참고: 가끔 등장하는 특수 방으로 강화 적 웨이브 클리어 시 희귀 가젯 획득 → 위험도 높은 방을 도전적으로 선택하는 능동적 의사결정 유도

## 전투 (04_Combat)

- **역할별 진동 차별화** — Controller Rumble 프리셋 참고: Cat 근접 히트 = 저주파 강진동(0.5, 0.8, 0.1s), Crop 발사 = 고주파 약진동(0.1, 0.6, 0.05s) → 두 플레이어가 컨트롤러만으로도 각자 역할 체감 가능
- **웨이브 클리어 보상 진동** — Boss Death 프리셋 참고: 방 클리어(모든 적 사망) 시 양 컨트롤러 동시 1초 강진동 → "클리어!" 감각을 손에서도 체감 → 협동 보상감 물리적 강화
- **패링 카운터 스포너** — Crop 방패 + Wave System 참고: Crop의 패링 성공 시 스포너가 해당 적 뒤에 약점 마커 활성화 (0.5초) → Cat이 그 타이밍에 돌격 슬래시 → 콤보 협동 메카닉

## 스토리 (05_Story)

- **Baron의 Sparklite 채굴** — Sparklite 세계관 참고: OnionCat 마왕은 양파 밭의 생명력인 "채소 에너지"를 채굴해 무기를 만드는 악당 → Cat은 "마을 대장장이", Crop(양파)은 마을의 생명력 그 자체 → "우리 마을을 되살려야 한다"는 동기
- **허브 마을 재건 서사** — Sparklite Fivestone Village 참고: 런마다 구출한 주민이 허브 마을에 귀환 → 처음엔 폐허였던 마을이 점차 활기를 찾아감 → 스토리 진행과 게임플레이 성장이 시각적으로 연동
- **Disruption = 양파의 눈물** — Sparklite Disruption + 양파 테마 결합: 런 실패(죽음) 후 세계가 재배열되는 것은 양파가 슬픔에 흘린 눈물이 세계를 씻어내는 것으로 설명 → 루프 메카닉에 감정적 의미 부여

## 기술 메모

- **적 스포너 & 웨이브 시스템**: `WaveData` ScriptableObject + `EnemySpawner` 컴포넌트 분리가 핵심. 적 사망 시 `OnDeath` 이벤트로 카운트 감소 → 0되면 `OnRoomCleared` 이벤트 → `RoomController`가 문 열기. 시작은 단순 `Instantiate` 방식으로 구현하고 적 수가 많아지면 `UnityEngine.Pool.ObjectPool<T>`로 전환.
- **컨트롤러 진동 & 햅틱**: `RumbleManager` 싱글턴 하나로 관리. 핵심은 **2인 플레이 시 `Gamepad.current` 대신 `PlayerInput` 컴포넌트에서 각자의 `Gamepad` 참조를 따로 보관**해야 독립 진동이 가능. 일시정지 메뉴 진입 시 반드시 `InputSystem.PauseHaptics()` 호출 잊지 말 것.
