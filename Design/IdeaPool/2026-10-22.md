## 캐릭터 (01_Characters)

- **전설 장비 = 빌드 정의 아이템** — PoE Keystone 참고: 지금 전설 3종(아홉 목숨·그림자 분신·황금 양파)은 강력하지만 "이 아이템을 기준으로 나머지 장비를 고른다"는 흐름까지는 아님. 새 전설 설계 시 "이 아이템을 장착하면 다른 슬롯의 선택지가 달라진다"는 컨셉 우선 — 예: "전설 무기: 할퀴기 쿨다운 없음 + 기본 피해 -50%" → 쿨다운 단축 장비가 쓸모 없어지고 피해 증폭 장비가 핵심이 됨
- **마법서 2~3개 조합 시너지** — PoE 소켓 링크 참고: Q·W·E 스킬 중 두 가지가 함께 있을 때 소량 보너스 발동. 예: 폭발+산탄 동시 보유 → 식물 박 터질 때 씨앗 3발 추가 발사. `GearEffect` `OnPlantExplode` 트리거로 구현 가능. 빌드 방향을 마법서 조합으로 표현하는 레이어가 추가됨

## 적 (02_Enemies)

- **세트 보너스 발각형 적** — PoE "리그 메카닉 적"에서 착안: 특정 적이 죽을 때 플레이어가 장착한 세트를 "감지"하고 해당 세트의 약점 속성으로 다음 공격 패턴 변경. 예: Sun 세트 2단계 이상 감지 → 죽으면 냉기 장판 생성(화상을 끔). 구현: `OnDeath`에서 `CombatModifiers.Has(SetId.Sun, 2)`로 분기
- **WFC 특화 적: 벽 변환자** — 근접하면 인접 바닥 타일을 구덩이로 바꾸는 적. WFC 시스템이 있으면 런타임에 타일 교체가 자연스러움. 없어도 현재 `Runtime_Tilemap_Modification` 기술로 구현 가능 — 단, 플레이어 발 밑의 타일을 미리 예고(노란 테두리)하고 바꾸는 것이 원칙 준수

## 맵·런 구조 (03_Maps)

- **WFC로 RoomChunks 대체** — 현재 3×3 덩어리 16종보다 풍부한 내부 배치: WFC로 방 내부만 채우면 이론상 무한 변형. 구현 선행 조건: 외곽 틀(벽·출구) 확정 → 내부 영역에 WFC 실행. 시드 재현 필수(`RoomLayout.GetHashCode() ^ stageIndex`를 시드로). 실패 시 폴백은 기존 16종 덩어리 중 하나
- **데모 전용 지도 설계** — Steam Next Fest 데모에서는 Stage 1(무너진 정원) 8층 지도만 노출. `RunMap`이 `DemoGate.IsDemo`를 확인해 1스테이지 후 성녀 궁수 방 고정 배치. 갈림길은 그대로 유지해 "나뭇가지 선택"의 즐거움은 보존

## 전투·협동 (04_Combat)

- **어피스 조합 힌트 팝업** — PoE 빌드 시너지에서 착안: 두 장비 효과가 조합 시너지를 이룰 때 "♻ 시너지: 대쉬 후 불꽃 적용"처럼 장비 화면에 힌트 1줄 표시. 모든 장비에 필요 없고 효과가 다른 효과를 트리거할 때만. 구현: `GearItem.synergyHint` 문자열 필드 → 장비 툴팁 하단에 표시. 플레이어가 빌드 방향을 더 빠르게 파악
- **협동 콤보 세트 연계** — PoE 어피스 조합 개념의 협동 버전: 특정 세트가 "협동 콤보 횟수"를 보너스 트리거로 쓰는 효과 추가. 예: Wind 세트 4단계 → "협동 콤보 5회마다 고양이·양파 동시 피해 폭발". 현재 `CombatModifiers`에서 콤보 카운트를 이미 추적하므로 새 Set 효과 추가만 필요

## 아이템·세트 (05_Items)

- **통화 다층 구조** — PoE 통화 = 제작 재료 개념 적용: 씨앗 외에 "강화 구슬"(희귀 장비의 특정 어피스 재롤) 같은 2차 통화 추가. 단, OnionCat은 심플한 게임이므로 과도한 시스템 복잡도 위험 있음. 먼저 "씨앗 + 상점 리롤"만으로 충분한지 플레이테스트 후 결정
- **데모 세트 집중 드랍** — 데모에서는 Sun·바람 두 세트만 집중 드랍 → 세트 시너지를 반드시 한 번 경험하도록. 풀 게임 10개 세트 중 2개만 보여주고도 "세트 보너스가 이렇게 강하구나" 느낌 전달이 목표. `RewardTable_Demo.asset`에서 해당 세트 가중치만 높임

## 스토리·메타 (07_StoryMeta)

- **리그 = 런: 이번 런의 특성** — PoE 리그 메카닉처럼 각 런에 고유 수식어 추가: "이번 런: 불꽃 계열 장비 드랍 20% 증가" 같은 런 수식어를 런 시작 화면에 표시. 구현: `RunData.runModifier` 필드 + 시작 배너 텍스트. 세이브에 포함해 이어하기 시에도 동일 수식어 유지. 단순하지만 "이번 런은 특별하다"는 기대감을 만든다
- **Next Fest 위시리스트 유도** — 데모 종료 화면이 Steam 위시리스트로 이어지는 감성 연결: "성녀 궁수를 물리쳤습니다. 양파의 여정은 계속됩니다..." 같은 한 줄 + "다음 이야기를 기다리려면" 위시리스트 버튼. 퀘스트 미리보기(현자 마법사·영웅 기사) 실루엣을 배경에 넣으면 호기심 자극

## 기술 메모

- **WFC 즉시 적용 경로**: 가장 적은 리스크로 적용하려면 `RoomChunks`의 ? 자리를 WFC 서브그리드로 교체. 외곽 틀·적 스폰 위치는 그대로 유지. 시드 = `room.GetInstanceID() ^ Random.seed`. 실패(모순) 시 폴백으로 기존 16종 덩어리 선택
- **데모 빌드 구현 순서**: ① `DEMO_MODE` 심볼 → ② `DemoGate.ShouldBlockProgress()` → ③ `DemoEndScreen` UI (30분) → ④ `RewardTable_Demo.asset` 장비 선별 (30분) → ⑤ Steam 데모 App ID 등록 (30분). Next Fest 신청은 행사 2~3개월 전 Steamworks 파트너 대시보드에서
