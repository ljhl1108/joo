## 캐릭터 (01_Characters)

- **패리 버프 릴레이** — Bravery and Greed 클래스 시너지 참고: Onion의 방어막 패리 성공 시 Cat에게 0.8초간 "슬래시 강화" 버프(데미지 ×1.5) 발동. AnimationEvent로 패리 윈도우 프레임을 정확히 제어하고, 패리 판정 성공 시 이벤트 발행 → Cat의 AttackSystem이 구독. 협력 타이밍 보상이 직접적으로 전투에 반영됨.

- **히트박스 프레임 퍼펙트 슬래시** — AnimationEvent 참고: Cat의 슬래시가 실제로 빠른 이유는 "히트박스 ON 프레임"이 3~5프레임에 불과하기 때문. AnimationEvent로 frame 3에 `EnableHitbox()`, frame 5에 `DisableHitbox()` 배치. 체감 타이밍이 빠르면서도 너그러운 판정(히트박스 크기를 시각보다 약간 크게) 유지.

- **공유 업그레이드 협의 칸** — Bravery and Greed 공유 골드/공동 상점 참고: 업그레이드 선택 화면에 "Cat 전용 1개 + Onion 전용 1개 + 공유 선택 1개" 3슬롯 구조 도입. 공유 칸은 두 플레이어가 동시에 버튼을 눌러야 확정 → 소통 강제. 단독 플레이 시 공유 칸은 자동으로 1개 추가 선택으로 대체.

## 적 (02_Enemies)

- **시전 예고 애니메이션 이벤트 적** — AnimationEvent 참고: 강한 적이 공격 전 "예고 모션" 애니메이션을 재생하고, 특정 프레임에 AnimationEvent로 경고 원 UI를 스폰. 경고 0.5초 → 폭발. 플레이어가 예고 시각 정보를 믿고 피할 수 있어 "불공평한 피격" 없음. 모든 보스 패턴에 표준 적용 가능.

- **역할 고정 협력 적 2종 조합** — Bravery and Greed 클래스 필요성 참고: "방어막 보호자"(Onion 원거리로만 방어막 제거 가능) + "돌진 추적자"(Cat 슬래시로만 처치) 동시 등장 방. 둘 중 하나만 처리하면 남은 적이 특화 위협 → 두 역할 동시 활성화 강제. 협력이 선택이 아닌 필수가 됨.

- **부활 방해 엘리트** — Bravery and Greed 부활 메카닉 참고: OnionCat이 "위기 상태"(HP 1 이하)일 때 주변에 달라붙어 부활 조건 달성을 방해하는 끈질긴 적. 다른 적과 달리 Cat과 Onion 모두의 공격에 취약 → 협력해서 빨리 제거해야 위기 탈출 가능.

## 맵 (03_Maps)

- **Bootstrap씬 기반 씬 전환 방 구조** — Bootstrap Scene 아키텍처 참고: 각 방(Room)을 별도 씬으로 분리하고 Additive Load로 교체. RoomManager가 클리어 감지 → 다음 방 씬 Additive 로드 → 이전 방 씬 Unload. 결과: 방 전환 시 플레이어/매니저 오브젝트 유지, 방 내부만 교체되어 로딩이 빠름.

- **협력 관문 방** — Bravery and Greed 역할 분담 참고: 방 중앙에 두 개의 레버가 있고, Cat이 근처 적을 막는 동안 Onion이 마우스로 멀리 있는 레버를 조준 클릭해야 문이 열리는 구조. AnimationEvent로 레버 조작 애니메이션의 특정 프레임에 `TriggerLeverActivate()` 호출.

- **파밍 선택 방** — Bravery and Greed 파괴 가능 오브젝트 참고: 항아리, 나무 상자 등 파괴 가능 오브젝트가 많은 보물 방. Cat의 슬래시로 한 번에 여러 오브젝트 파괴 → 재화 획득. 시간을 써서 파밍할지, 바로 다음 방으로 갈지 선택지 제공.

## 전투 (04_Combat)

- **애니메이션 프레임 기반 패리 윈도우** — AnimationEvent 직접 적용: Onion의 패리 가능 프레임을 AnimationEvent로 정확히 제어. `EnableParryWindow()` (frame 0), `DisableParryWindow()` (frame 2), `EnableBlockWindow()` (frame 3), `DisableBlockWindow()` (frame 8). 이 방식으로 "패리 윈도우=2프레임, 방어 윈도우=5프레임" 정밀 구분 → 숙련도에 따른 보상 차등 가능.

- **협력 콤보 시스템** — Bravery and Greed 클래스 시너지 직접 적용: (1) Onion 패리 성공 → (2) Cat 슬래시 강화 → (3) Cat 강화 슬래시 적중 → (4) 주변 소형 AoE. 세 단계가 연속으로 터질 때 화면 피드백(히트스톱, 파티클, SFX 레이어) 극대화. AnimationEvent로 각 단계의 이벤트 타이밍 정밀 제어.

- **발소리 + 보행 SFX 프레임 싱크** — AnimationEvent 실용 적용: Cat 걷기/달리기 애니메이션에 발이 닿는 프레임에 `PlayFootstep(int surfaceType)` 이벤트 추가. 바닥 타일 타입에 따라 발소리 클립 교체(흙, 돌, 물웅덩이). Update()에서 타이머로 관리하는 것보다 발소리 타이밍이 시각과 정확히 일치.

## 스토리 (05_Story)

- **협력이 결속을 만든다** — Bravery and Greed 공동 여정 참고: Cat과 Onion이 처음엔 어색한 동반자지만 위기 상황을 함께 넘기면서 신뢰를 쌓는 서사. 각 던전 레이어 클리어 후 짧은 대화 컷씬으로 관계 변화 표현. 스토리가 게임플레이 협력 강도와 자연스럽게 연동됨.

- **누가 Bootstrap씬을 관리하는가?** — Bootstrap 씬 아키텍처 참고 (메타적 아이디어): 게임 내부의 "세계 유지자" 캐릭터가 존재 — 세계의 씨앗(Onion)이 사라지면 세상이 무너진다는 설정. GameManager가 런 데이터를 영구 보존하듯, Onion이 세계의 "지속성"을 상징하는 역할.

- **씬 별 분위기 레이어** — Bootstrap + Additive Scene 참고: 런 초반(숲 방 → 따뜻한 조명), 중반(동굴 방 → 어두운 조명), 후반(보스 구역 → 붉은 조명). 각 방 씬에 Light2D 설정을 담아 Additive 로드 시 분위기 자동 전환. Bootstrap의 AudioManager가 BGM도 씬 전환에 맞춰 크로스페이드.

---

## 기술 메모

- **AnimationEvent**: 히트박스 ON/OFF, 투사체 발사, SFX/VFX 재생 등 "애니메이션과 동기화가 필요한 모든 것"에 적용. Update()에서 타이머로 관리하는 방식은 프레임레이트 의존 문제가 있고, 애니메이션 교체 시 로직도 함께 수정해야 하는 결합도 문제가 있음. AnimationEvent로 관리하면 애니메이터가 로직 타이밍을 직접 제어 → 디자이너와 프로그래머 분업 가능.

- **Bootstrap Scene 아키텍처**: OnionCat에 당장 적용해야 할 씬 구성은 `0_Bootstrap → 1_MainMenu → 2_Gameplay → 3_GameOver` 순서. Bootstrap에서 GameManager(런 데이터), AudioManager(BGM/SFX), InputManager(Cat 조작/Onion 마우스) 세 매니저를 DontDestroyOnLoad로 생성. Build Settings에서 Bootstrap이 반드시 인덱스 0에 위치해야 앱 시작 시 자동 실행됨.
