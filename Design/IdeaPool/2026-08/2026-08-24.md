## 캐릭터 (01_Characters)

- **신의 축복 수령 연출** — Death Must Die 참고: 업그레이드 선택 화면에서 특정 신이 등장해 대사를 건넴. OnionCat에서 고양이와 파가 각각 다른 반응을 하도록 — 고양이는 근접 강화를 좋아하고, 파는 원거리 강화를 선호하는 성격 대사 추가. 구현: `UpgradeSelectionUI`에 `characterLine` 딕셔너리, 업그레이드 태그(Melee/Ranged)에 따라 대사 선택.

- **파(Crop) 공중 흔들림 그림자** — Blob Shadow 참고: 고양이가 달릴 때 화분이 흔들리는 느낌을 그림자로 강화. 고양이 발 그림자(크고 납작)와 화분 그림자(작고 별도)를 분리해 2개 그림자를 유지. 이 두 그림자의 합성이 "둘이 하나" 컨셉을 시각적으로 표현.

- **부활 코인 연출** — Resource Feedback 참고: 파가 처치됐다가 부활할 때, 저장된 "파 생명력 구슬"이 HUD에서 월드로 역방향으로 날아와 파에게 흡수되는 연출. `PlayCoinFly`의 시작/끝을 역전시켜 구현.

## 적 (02_Enemies)

- **방패병 (근접만 취약) + 원거리 명사수 (원거리만 취약) 쌍 등장** — Death Must Die 참고: 이 두 적이 같은 방에 동시 등장 → 협력 강제 상황 창출. 방패병은 고양이(P1)가, 명사수는 파(P2)가 담당해야 함. 구현: `EnemySpawnerWaveSystem`에서 "강제 협력 웨이브" 플래그 추가.

- **그림자 없는 유령 적** — Blob Shadow 참고: 일반 적은 바닥 그림자가 있지만 "유령형" 적은 그림자 없이 등장 → 플레이어에게 이 적이 다름을 즉각 인식시킴. 시각적 구분자로 활용. 구현: 유령 적 프리팹의 Shadow 자식 오브젝트를 비활성화.

- **수확 몬스터 (코인 드롭 특화)** — Resource Feedback 참고: 처치 시 다량의 골드를 드롭하는 "수확 몬스터" 유형. 처치 순간 10개 코인이 폭발하듯 날아가는 연출로 처치 보람 강화. 구현: `SpawnMultipleCoinFeedback(origin, 10)` 호출.

## 맵 (03_Maps)

- **신탁 방 (업그레이드 선택 전용)** — Death Must Die 참고: 신이 나타나 은총을 주는 전용 방 타입. OnionCat에서 특수 방(상점, 치유, 신탁)을 각각 아이콘으로 구분해 문 위에 표시. 신탁 방에 입장하면 BGM이 부드럽게 전환. 구현: `RoomType` enum에 Oracle 추가, 문 위 UI 아이콘 표시.

- **넓은 아레나 + 좁은 복도 교차** — Death Must Die 참고: 드넓은 아레나에서 웨이브를 처리하고 좁은 복도로 이동하는 리듬. 좁은 복도는 파(P2)의 원거리 공격이 빛나는 구간 → 원거리 전략 강화 레이아웃.

- **바닥 타일 그림자 영역** — Blob Shadow 참고: 특정 방에 실제 어두운 구역(빛이 없는 타일)을 배치. 이 구역에서는 적의 Blob Shadow가 보이지 않아 위치 파악 어려움 → 난이도 변수. URP 2D Light로 어두운 Zone 연출.

## 전투 (04_Combat)

- **파+고양이 동시 타격 시너지** — Death Must Die 참고: 같은 적이 같은 프레임에 근접 + 원거리로 동시에 맞으면 "협동 보너스 피해" 발생 (예: +50% 피해 + 특수 파티클). 구현: `DamageSystem`에서 동일 프레임(또는 0.1초 이내) 이중 타격 감지 → `ComboDamageMultiplier` 적용.

- **골드 코인 흡수 대시** — Resource Feedback 참고: 대시 중 코인을 지나치면 자동으로 흡수(磁力) + 전방으로 코인이 날아오는 연출. 대시를 더 적극적으로 쓰게 만드는 인센티브. 구현: 대시 상태에서 픽업 콜라이더 반경 2배 확대.

- **웨이브 클리어 폭발 코인 보상** — Resource Feedback + Death Must Die 참고: 방 클리어 시 가장 강한 적 위치에서 "보상 폭발" — 다수 코인이 사방으로 튀기며 플레이어에게 날아옴. `SpawnMultipleCoinFeedback`으로 5~15개 동시 처리. 코인 수는 방 난이도에 비례.

## 스토리 (05_Story)

- **파의 신탁** — Death Must Die 신 캐릭터 참고: OnionCat 세계에서 파(Crop)는 고대 대지의 작물 정령에게 연결돼 있음. 업그레이드 선택 시 정령이 파에게만 들리는 목소리로 속삭임 → 고양이는 "파가 왜 갑자기 빛나지?" 하는 반응. 두 캐릭터의 다른 시점이 드러나는 서사 레이어.

- **그림자 = 과거의 흔적** — Blob Shadow 참고: 세계관에서 "그림자를 잃은 존재는 영혼이 없다"는 규칙 존재. 최종 보스는 그림자가 없음 → 시각적 단서로 먼저 알 수 있음. Blob Shadow를 의도적으로 없애는 연출로 이야기와 기술이 연결.

- **수확의 저주** — Resource Feedback 참고: 파는 원래 평화로운 농장의 작물이었음. 게임 속 수집 자원(코인, 파편)은 사실 저주받은 세계의 파편 — 수집할수록 파의 몸이 점점 변해가는 스토리 진행. 코인 수집 애니메이션에 저주 파티클 효과를 런 후반에 추가.

## 기술 메모

- **Blob Shadow System**: `BlobShadow.cs`에서 `LateUpdate()`로 캐릭터 위치를 추적해야 그림자가 한 프레임 지연되지 않음. 그림자 스프라이트를 별도 Sorting Layer "Shadow"에 배치해야 캐릭터 발아래 정확히 렌더링됨. **가장 빠른 구현은 방법 1(정적 자식)** — 점프 없는 탑다운이라면 스크립트 없이도 완성 가능.

- **Resource Collection UI Feedback**: `RectTransformUtility.ScreenPointToLocalPointInRectangle()`로 월드→캔버스 좌표 변환이 핵심. Canvas의 renderMode(ScreenSpaceOverlay vs Camera)에 따라 두 번째 인자(`camera`)를 달리 넘겨야 함. DOTween 있으면 `transform.DOMove(target, duration).SetEase(Ease.InBack)` 한 줄로 대체 가능.
