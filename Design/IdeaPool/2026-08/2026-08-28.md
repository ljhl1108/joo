## 캐릭터 (01_Characters)

- **씨앗 폭탄 작물** — Noita 스펠 조합 참고: Player 2의 기본 투사체가 적에 맞으면 땅에 떨어져 씨앗이 심어지고, 냥이(Player 1)가 그 위를 지나가면 폭탄이 활성화 → 협동 연계기 구현 힌트: Projectile의 OnTriggerEnter2D에서 "씨앗 오브젝트" Spawn, 별도 Trigger로 냥이 감지 후 폭발
- **파닥 작물(날개 달린 작물)** — 세피리아의 캐릭터 다양성 참고: 특정 런 업그레이드로 Player 2 작물이 짧게 부양(hover) 가능 → 냥이가 낮은 지형을 이동할 때 Player 2 시야각이 더 넓어지는 효과, 구현 힌트: Player 2 위치를 CropFollower 스크립트에서 offset Y 값을 lerp로 조정
- **무장 봉오리 스킨** — 픽셀아트 색상 참고(세피리아): 업그레이드 단계별로 작물 스프라이트 변화 (새싹 → 꽃봉오리 → 활짝 핀 꽃), 전투력이 시각적으로 표현됨, 구현 힌트: Sprite 배열을 ScriptableObject에 보관, 업그레이드 이벤트에서 SpriteRenderer.sprite 교체

## 적 (02_Enemies)

- **자폭 버섯 적** — Noita 물리 연쇄반응 참고: 죽을 때 포자를 4방향 살포 → 포자가 다른 적 또는 플레이어에게 닿으면 추가 피해, "근접 공격 약점" 적으로 냥이가 근접해야 처치 가능, 하지만 자폭 범위 안에 있으면 냥이도 피해 → Player 2의 원거리 지원으로 포자 상쇄 유도, 구현 힌트: 적 사망 이벤트에서 SporeProjectile 4개 Instantiate
- **거울 방패 근위대** — Noita 반사 참고: 원거리 공격을 정면에서 반사하는 방패를 가진 적, "근접 공격 약점"이지만 앞쪽은 원거리 반사 → 냥이가 측면/후면으로 접근해야 처치, 구현 힌트: 방패 방향(transform.right)과 투사체 입사각을 Dot Product로 비교, 반사 조건 충족 시 velocity = reflect
- **세피리아 스타일 다중 페이즈 정예 적** — 체력 50% 이하에서 패턴 변화: 1페이즈(원거리 약점) → 2페이즈(근접 약점)로 전환, 두 플레이어가 역할을 전반/후반으로 바꿔야 하는 구조, 구현 힌트: EnemyHealth에서 OnHealthThresholdCrossed 이벤트 발행, EnemyAI에서 구독하여 WeaknessType과 공격 패턴 교체

## 맵 (03_Maps)

- **노이타식 액체 함정 방** — 물 웅덩이가 바닥에 깔린 방: 물 위의 적에게 Player 2 전기 투사체 업그레이드 시 연쇄 피해 가능, 구현 힌트: 물 영역은 Trigger2D Collider + "Water" 태그, Projectile이 Water 감지 시 주변 원형 OverlapCircle로 추가 피해
- **세피리아식 층 구조 단계별 방 선택** — 방 클리어 후 두 개의 출구를 플레이어가 선택: 좌측(상점 방 확률↑) vs. 우측(전투 방 확률↑), 협동 합의가 필요한 선택 연출, 구현 힌트: RoomExit 컴포넌트에 ExitType enum(Shop, Combat, Treasure) + 가중치 랜덤 결정
- **씨드 기반 비밀 방** — Noita 평행세계 참고: 특정 씨드 런에서만 등장하는 히든 방, 일반 런에서는 벽이 두꺼워 보이지 않음, 구현 힌트: 씨드 값 해시로 특정 조건 충족 시 HiddenRoom 프리팹을 추가로 배치

## 전투 (04_Combat)

- **스펠 조합 업그레이드** — Noita 스펠 조합 참고: Player 2의 업그레이드 아이템 두 개를 동시에 보유할 때 "조합 시너지" 자동 활성화 (예: Triple Shot + Piercing → 관통 삼연속탄), 구현 힌트: 업그레이드 리스트를 HashSet으로 관리, 두 아이템 ID 조합 Dictionary로 시너지 효과 조회
- **패리 → 충전 발사** — Player 2 방패 패리 성공 시 "충전 게이지" 획득, 게이지 풀 차면 강화 탄 발사 가능, 협동 동기부여(냥이가 적 유인 → 작물이 패리 → 강화탄 발사), 구현 힌트: ParrySuccess 이벤트에서 ChargeGauge += parryBonus, 게이지 풀 시 ShotPattern을 일시적으로 Fan으로 교체
- **죽음 원인 표시 UI** — Noita의 "왜 죽었지?" 학습 루프 참고: 게임 오버 화면에 "마지막 피격 적 타입 + 공격 타입" 표시 (예: "원거리 적의 탄에 맞음"), 구현 힌트: PlayerHealth.OnDeath 이벤트에서 마지막 DamageSource를 GameOverManager로 전달

## 스토리 (05_Story)

- **노이타식 세계 영속성 서사** — 냥이가 죽으면 이전 런의 흔적이 남는다: 무덤 오브젝트가 다음 런에 해당 방에 등장, 무덤을 지나가면 이전 런의 마지막 획득 업그레이드 하나를 이어받을 수 있음, 구현 힌트: 런 종료 시 사망 위치와 마지막 업그레이드를 PlayerPrefs/JSON에 저장
- **작물의 성장 서사** — 세피리아의 캐릭터 성장 시스템 참고: 런을 거듭할수록 작물(Player 2)이 대사로 자라남, "아직 꽃이 피지 않았어요"(1~3런) → "이제 괜찮아요"(10런 이상), 구현 힌트: 총 런 횟수를 PlayerPrefs에 저장, 대화 시스템에서 런 횟수 범위별 대사 배열 선택
- **냥이와 작물의 대화** — 방 이동 중 두 플레이어 캐릭터 간 짧은 대화 이벤트 (텍스트 버블로 표시): 냥이 "앞에 뭔가 있어", 작물 "내가 먼저 쏠게요", 구현 힌트: 방 입장 시 RandomDialogue 목록에서 룰에 따라 선택, Canvas World Space 버블로 각 캐릭터 머리 위에 표시

## 기술 메모

- **Player 2 원거리 전투 패턴**: 가장 먼저 구현할 것 → `ShotPattern.Single`만 완성하고 나머지는 업그레이드 픽업에서 `currentPattern`을 교체하는 방식으로 확장. ScriptableObject(`ProjectileData`)로 데이터 분리하면 밸런싱이 코드 없이 Inspector에서 가능. 취약점 체계(`EnemyHealth.WeaknessType`)와 투사체 소스 파라미터(`isMelee: false`)를 처음부터 연결해야 나중에 리팩토링 비용 줄어듦.

- **듀얼 플레이어 입력 리바인딩**: `InputActionAsset`에서 Player1/Player2 Action Map을 분리하는 것이 최우선. 리바인딩은 게임의 핵심 기능 완성 후 추가해도 늦지 않음. 단, `SaveBindingOverridesAsJson()` + `PlayerPrefs` 저장 로직은 처음부터 넣어두면 QA 중 설정이 날아가는 불편 방지. 마우스 Position 액션은 리바인딩 UI에서 숨길 것.
